《营收只有 AWS 的 1%，Nebius 的 CTO 讲清了 AI 云的窗口期》

一座 30 兆瓦的数据中心，五年前算是相当像样的设施，能塞进几十万台服务器。现在它有时候连一个客户都喂不饱。

这句话来自 Nebius 的 CTO。他在这期 Unsupervised Learning 里跟主持人 Jacob Effron 聊了一个多小时，主题是 AI 云这个行当到底怎么运转。Jacob 是 Redpoint Ventures 的投资人，平时专门找 AI 研究者和创业者聊天。这一期的信息密度相当高，从 Yandex 拆分、NVIDIA 新卡上线、客户分层，一直讲到五年后这个市场会剩下几家。

先说个数字做参照：Nebius 今天的营收大约是 AWS 的百分之一。而这位 CTO 说，他们的下一个竞争坐标就是 AWS 和 Google Cloud。

从 Yandex 拆出来的一支硬件队伍

Nebius 的来历得从 2024 年说起。那年公司完成与 Yandex 的拆分，俄罗斯资产彻底剥离，从头开始。

这段历史对后来的业务影响很大。Nebius 的硬件团队核心成员来自 Yandex，那批人运营过真正的超大规模基础设施，几十万到上百万台服务器，跨多个机房。CTO 说得很直接：如果没有这支核心团队，公司会远没有今天这么顺利。硬件这块路径清晰，需要经验，他们恰好有经验，于是从第一天就开始建。

软件那头完全是另一回事。整个平台推倒重写，之前的积累基本作废。到 2024 年底新平台上线时，软件工程团队里相当一部分人已经不是 Yandex 出身，因为那两年不得不大规模招人。

他给了一组很能说明问题的数字。2024 年，负责采购 GPU、建机房、写固件、搭网络的那支硬件队伍大概四五十人；同一时间软件组织已经有两百人。「我们更愿意把自己看成一家软件优先的公司，只是把云建在扎实的硬件地基上。」

他还顺手点评了同行：很多做 AI 云的人是加密货币或能源出身，思路是买卡、让卡跑起来、再去找买家。Nebius 从第一天选的是另一条路，做完整的云平台，不做托管裸金属，不做第三方服务的拼盘。

一张卡卖半小时，也卖一万张卡的集群

主持人抛了个「稻草人」：听众可能觉得，AI 云嘛，能拿到 GPU 就行，谁有卡就去谁那儿。

CTO 的回应是从产品定义开始的。同一个平台，既要把几万张 GPU 连成一个互联集群服务大客户，也要让自助客户租一张卡跑半小时。这两件事跑在同一套软件上，是这家公司从第一天定下的价值主张。他管这个叫「把大规模基础设施零售化」。

顺便说个行业黑话的演变。「neo cloud」这个词，圈内人讨厌得很。刚出现时它是个区分标签，那时候被这么叫的公司只有五到七家。现在按宽泛口径数，三百到五百家都有可能。用他的话说，这把伞撑得太大了，「我们是 AI 云，别人爱叫什么叫什么」。

新芯片进机房，是一团「好的混乱」

这部分是我觉得最有画面感的。

NVIDIA 会提前很久把下一代产品的原型和图纸给到合作伙伴：内部怎么优化、PCI 连接怎么走、未来平台长什么样。过一阵子人又来了，说我们优化过了，方案要改。再过一阵子，第一批实验室样品到了，「顺便说一下，它跟两个月前给你看的不一样了」。

「他们把芯片投产的过程和迭代的过程压在一起了。消费电子不是这样，你今天看到的 iPhone，三年前就规划好了，最后一年基本是打磨。AI 市场跑得太快，发布会上讲的东西只是个方向，团队一直在改。」

等样品接近量产版本，云厂商的活才真正开始：把新硬件的支持和限制写进软件平台，解决虚拟化、存储、网络、多租户隔离。有些代际上，Nebius 是最早搭出某个规模集群的团队之一，于是撞上了没人见过的软件问题，得报给 NVIDIA，提 patch，等修复，再验证一遍。

他还讲了一个架构层面的变化。做 B300 那类机器时，运维单位是服务器，出问题关掉一台，把负载挪走就行。到了 GB300，单位变成了机架，隔离方式、维护方式全都不一样，得想办法在整个机架上做运维。这种跨越没法靠买现成方案解决，只能自己在软件层啃。

至于 NVIDIA 和 Groq 那笔交易带来的新加速器，他的定位很冷静：是平台的局部补充，是个「半代」的新东西，连接方式有点怪，能跑的负载也有限制，跑过几代产品的人不会觉得天塌了。

客户真正的分水岭，不在性能

被问到不同客户的诉求差异，CTO 先泼了盆冷水：负载其实就训练和推理两类，性能要求没那么五花八门。

真正被低估的是存储。他提到自己上一份工作里，谈网络存储用的是每秒几百兆到几 GB 的口径。现在他们有客户 routinely 从单个共享卷读到每秒 500 到 700 GB，这个卷接在上千台服务器、8000 张卡上，文件系统三 PB 起步。「两年前我根本不会想这个数字，现在它算是常态。」另一个好处是，把最苛刻的客户伺候好了，基线自然高到能服务所有人。

客户之间真正的分野，是成熟度和责任。新兴实验室签的是十亿美元级别的合同，他们在乎的东西极少：GPU、存储、性能、可用性。至于机房在美国、欧洲、法国还是冰岛，很多人根本不问。网通、存储够快、卡能跑，就这么简单。

企业客户合同小得多，有时候小很多，但对方有客户、有义务、有跨多国的合规要求。于是 Nebius 开始进另一套流程：认证、合规、安全姿态审查、「让我们看看你们的源码」、「你们怎么防这个攻击面」。CTO 说，这半年他们才真正进入「做一朵真云」的阶段。

推理这块地，行业还没开始耕

主持人问到 prefill 和 decode 分离，这话题最近很热。

CTO 的回答很不客气：「所有人都在谈，没人真做对。」原因是 SLA 和可运维性太难，而推理这条链上还有一堆更容易摘的果子。他们有生产环境下的分离部署，但服务的是最挑剔的那几个客户，方式更接近手工调优，没做成所有客户的默认方案。

他还提了个反直觉的点：GB300 机架内的互连太快了，很多原本必须靠分离来解决的问题，只要装进一个机架的 footprint 里就消失了。剩下的工作是按客户的流量特征去调配 compute 和内存的配比。

再往下一层，他说了句很重的话：「作为一个行业，我们什么都没优化好。」原版开源模型直接拉起来跑，效果通常令人失望，不快也不便宜。但 95% 的客户根本不跑原版模型，他们跑的是微调过的、改过的版本。

这一点指向一个被低估的方向。当场景收敛到有限领域，你就未必要那么大的模型，可以剪枝、可以压缩、可以用投机解码，把模型砍到只在这个任务上表现好。他为此在夏初收购了一家做模型优化的公司，团队翻倍到几十人，分成 kernel 优化组和模型压缩组。

另一笔收购是 Tavily，做面向 AI 的网页搜索，差不多是一年前的事。逻辑是产品本身和 GTM 节奏都不错，加上 Nebius 在大规模索引和底层基础设施上的能力能帮它跑得更快。这条路还在往 agent 工具、sandbox、managed inference 的组合上走。

超大厂为什么没一口吃掉这块市场

这是全篇最有价值的一段分析。

第一层原因很物理：芯片不够。CTO 给了个假设，如果 NVIDIA 能产出十倍的芯片，整个市场格局会完全不同。微软和谷歌会同时给内部和外部市场买产能，现在的局面根本不会形成。产能不够，这门生意对它们就只是几十亿美元的小盘子，相对整体营收不算什么。

第二层是内部拉扯。这些公司自己就是 AI 重度用户，训练要卡、推理要卡、研究要卡，还要在「内部团队用」和「拿去出租」之间反复权衡。

第三层最硬：改造既有基础设施。为别的负载建起来的网络、吞吐、存储性能，要整体适配 GPU 云，这是一笔巨大投资，得有足够大的潜在生意来justify。而现在这块生意还不够大。

所以他给的时间表是：等芯片短缺缓解，两到五年，超大厂一定会回来，会重组、会重新设计内部架构、会用销售力量来抢。真正的悬念是，那时候新玩家有没有长到能跟它们平起平坐的量级。

瓶颈只有一个：执行力

主持人请他给当下的瓶颈排个序，他拒绝排序，理由是瓶颈遍地都是：GPU 缺、CPU 缺、NVMe 缺、机柜缺、电力缺、合格的施工队伍缺、光模块这种小部件也缺。

然后他补了一个很多人没注意的：变压器。交期以年计。

既然每个环节都卡，唯一能施加影响的变量就是执行力。采购能力、在合适的地方做取舍、把设备从一个机房搬到另一个机房再搬回来、这周推迟这个、下周赶上那个。他说，自己整个职业生涯里，从没见过对项目经理的需求像现在这么高。

组织上，他站保守那一侧

Nebius 内部对 AI 编码工具不设人均上限，预算给得很足，也不按部门卡额度。但他们看用量、看用法，专门去翻那些最低效的使用方式。

政策的核心只有一句：不管你用了什么 agent，结果仍然是你的结果。你的 PR、你的代码、半夜被叫起来处理故障的人，还是你。完全自主的 agent 生成的代码必须打标记，而且短期内不许碰核心服务。

他还提到自己一年内改变的看法：AI 编程。一年前他觉得那玩意儿基本是废物，现在已经是他日常工具箱里很扎实的一部分。他个人也开始依赖本地 agent 来分担一部分认知负荷。

至于他最近盯的方向，已经不在模型有多大、多聪明。他更关心长周期 agent 的「结果优化」：怎么通过更精细或更简化的工具、为特定任务演化的 harness，提高拿到正确结果的概率，同时把成本压下来。一个有意思的观察是，这条路会重新推高 CPU 消耗，因为很多现代 agent 执行流最后会落回代码，有质量门、有复杂工具调用，agent 跑上几分钟，一次 LLM 请求都没发。

五年后这个市场长什么样

三百到五百家 AI 云，五年后还剩几家？他说不确定，但确定会有长尾的位置。

类比很清晰：AWS 旁边站着 Hetzner、DigitalOcean、Linode，还有一堆本地托管商。DigitalOcean 没有因为 AWS 变大而死掉。数据库领域也一样，AWS 有 Aurora 和 Redshift，Snowflake 和 MongoDB 照样从夹缝里长成了大公司。细分不等于小，细分可以是一门很扎实的生意。

他还点评了 OpenAI 和 Baseten 的合作：客户抱怨闭源模型太贵，给一个便宜的开源选项，能留住人就行，只要人还在自家生态里，就有向上销售的空间。他认为这类动作说明大模型公司在试探边界，而不是把边界画死。

明天就能用的几件事

  • 给自己的 AI 项目留一条退出路径。Nebius 90% 以上的差异来自软件而不是硬件，意味着你选的供应商换掉之后，迁移成本取决于你的抽象层做得多干净。现在就检查一遍，你的推理服务是不是绑死在某家的 SDK 上。
  • 认真算一遍共享存储的吞吐。如果你在做大规模训练或多 agent 并发，瓶颈很可能不在卡上。单个卷跑到几百 GB/s 已经是头部客户的常态，你的架构扛得住吗？
  • 把模型压缩当成一等公民。95% 的生产负载都不是原版模型。如果你的场景已经收敛，先想剪枝和蒸馏，再想加卡。
  • 制定一份 agent 产出责任规则。哪怕团队只有五个人。核心服务不许全自主 agent 直接改，agent 生成的代码要可追溯，on-call 的人必须是人。
  • 把「项目管理能力」当成基础设施建设的一部分。采购、排期、跨机房调度，这些在短缺时代比多买两张卡更能决定交付时间。
