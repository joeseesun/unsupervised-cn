《OpenAI 首位 DevRel：九成代码靠 ChatGPT，智能体上网还得等几年》

ChatGPT 上线一周年时，官方公布的数字是一亿周活跃用户。Redpoint Ventures 的 AI 播客 Unsupervised Learning 这期请到的 Logan Kilpatrick，正好卡在这条时间线的起点上。他是 OpenAI 招的第一位开发者关系（DevRel）员工，入职比 ChatGPT 发布还早，正式上班那天，产品刚过一百万用户。

一年，一百倍。这期节目里，他把开发者生态的一线观察摊开讲了一遍：大家怎么用 API，OpenAI 内部怎么排优先级，插件为什么没成，智能体为什么还上不了网，还有不少他自曝的一手细节。

先说他的日常。主持人 Jacob Effron 问他自己怎么用 ChatGPT，答案很朴素：写代码。他有计算机科学背景，做过软件工程师，但网页开发不熟，脑子里有明确的产品想法，翻译成代码经常卡壳。

「我上线的一半功能，大概九成代码是 ChatGPT 写的。」

他的原话是，这些工具让他不用再花十三个小时啃 React 文档。管着 OpenAI 开发者平台的人，自己就是最重度的用户，顺便把产品调研也做了。

模型怎么选：三四条指令是条分界线

开发者问得最多的问题：GPT-3.5 和 GPT-4 用哪个？Logan 给了一条具体的判断线。一条提示词里塞到三四条指令，是 3.5 Turbo 的能力边界，超过这个数，性能开始崩，该换 GPT-4 了。跟人一样，同时记三件事还行，记八件事必丢三落四。

不过他补了一句，Dev Day（OpenAI 首届开发者大会）大降价之后，很多人直接从 GPT-4 起步，懒得再折腾 3.5，省下的调试时间比差价值钱。

想留在 3.5 也有办法：微调。3.5 微调功能发布时，OpenAI 在博客里写过，不少早期客户靠微调加提示词工程，把 3.5 调到了 GPT-4 的水平，还顺带省了 token。

整期节目最实用的一个技巧，是函数调用的省钱玩法。假设你的应用挂了五十个函数，每次请求都得把五十个函数的定义塞进提示词，token 费用每次都付。Logan 的方案是，用大量函数调用数据去微调 3.5，把这些定义从提示词里彻底拿掉。

「模型本质上是把函数幻觉出来，听起来很怪，但对开发者是好事，你不用每次都付那五十个函数的 token 成本了。」

再往上一层，是 Dev Day 发布的定制模型（Custom Models）。门槛他讲得很直白：需要数十亿 token 的高质量数据，而且得是模型本来不擅长的领域，比如法律、医疗，预算大概两到三百万美元。OpenAI 的研究团队会亲手带着客户做，因为这事光有数据没用，还得有像样的机器学习能力。

主持人问，基础模型越来越强，定制模型会不会只是过渡需求。他的判断相反：定制模型会一直存在。基础模型会变得更可引导，但永远盖不住所有细节。未来还有优化空间，比如从训练集里剔除模型不需要的数据，做出更省算力的定制版本。

开源模型呢？Logan 入职 OpenAI 之前，长期参与 Julia 编程语言的开源生态，用他的话说，开源流淌在他的血液里。但他的判断很明确：闭源大模型会一直比开源强，训练真正的大模型，成本和工程量摆在那里。

开源的合理场景有两个：一是业务上必须掌握模型权重和知识产权；二是 Llama 这类模型允许更深度的定制，比如 RLHF，OpenAI 的标准微调暂时不提供，他暗示这块以后会补上。至于自己部署开源模型，光搞到 GPU 就够呛，很多团队算下来还是直接调 API 省心。

插件没成，但 GPTs 把作业补上了

复盘这一年，Logan 承认插件（Plugins）是最接近失败的发布。上线前他觉得这就是大家要的答案，外界也在喊「下一个 App Store」。结果反响平平。

他现在重新定性：插件更像一次研究预览，跟 ChatGPT 最初的定位类似，只是被包装成了产品发布。设计上有硬伤，要求开发者把一份公开托管在互联网上的 manifest 文件挂出来，配上 OpenAPI 规范，从产品角度看实现得不好。

还有个更现实的原因：人手不够。插件团队上线之后，人马上被抽去赶浏览功能和代码解释器，后面还排着无数新东西。插件就这么被晾在那儿了。

但探索没有白费。GPTs 基本把插件时代没做成的几件事补齐了：以前开发者想要「浏览加我的插件加代码解释器」，做不到，现在可以随意组合；涉及敏感操作时如何征求用户同意这类安全难题，也在 GPTs 框架里有了答案；即将推出的 GPT 商店，会解决插件商店只有基础搜索和几个分类的发现性难题。

至于 GPTs 目前的真实使用情况，他的观察有点泼冷水：大部分用例还是围绕分享提示词。最火的 GPT 集中在编程和建站，一套写得好的 instructions 确实能带来很大加成。自定义动作（Custom Actions）用的人还少，因为要填 OpenAPI 规范，不会写代码的普通人过不了这道坎。

顺着聊到那个流行说法：提示工程要死了。他的回应值得记下来。提示工程的本质是沟通，而人类用手指打字的时候，天生就是懒惰的沟通者。他期待模型朝 DALL·E 3 的方向演进：你输入一段话，系统先改写成更完整的提示词再交给模型，中间加一层翻译。以后你只需要把想要的说清楚，啰嗦的部分交给机器补。

快问快答环节，主持人问他 AI 领域什么被高估、什么被低估，他答得干脆：被高估的是提示工程，被低估的是可观测性。真在搭东西的人，不管自建还是买现成产品，都得想办法看清模型背后发生了什么。

视觉还停在 GPT-3.5 时代

Logan 之前在演讲里说过「明年是多模态之年」，主持人以为他会把宝押在视觉上。他给了个更冷静的版本：视觉模型今天还处在「GPT-3.5 视觉时代」。

他的逻辑是这样的。很多真正酷的用例，要求模型对图像里物体的位置关系有非常细的理解。模型现在做得不差，但很多场景要等到「完美」才能用。这就像 GPT-3.5 和 GPT-4 的差距，一旦跨过那个台阶，一批新用例会突然解锁。

他举了两个自己的痛点。一个是他重度使用 Canva，做过几百个设计，但视觉模型今天读不懂那些模板里元素的空间关系，没法跟他说「把这个排版重排一下」。另一个是 DALL·E 生成图片里的文字，经常就错几个字符，可你没法像在 Photoshop 里那样点进去改。怎么让 DALL·E 的输出变得可编辑，他觉得是个重要到没人给出答案的问题。

顺带一提，Dev Day 上排在发布清单第七第八的文字转语音（TTS），他评价极高，说自己玩了几个月 demo。这个领域 ElevenLabs 做得很出色，分发做得好，但更偏消费者和内容创作者，开发者会不会迁移到 OpenAI 的 API，他觉得有意思。

他最想看到的两个产品

主持人 Jacob 在节目结尾把 OpenAI 的打法概括成 AI 界的 AWS：微调、定制、评测、企业方案全都要自己做。创业公司的机会在哪些缝里？Logan 给了两个非常具体的答案。

第一个是文本优先的 AI 助手。用 Assistants API 接上 Twilio 这类短信服务，用户直接发短信就能用上助手。他的理由是，人的想法经常出现在发短信和写邮件的时刻，可市面上的 AI 助手产品全都要人跳去一个新网站、导入 Gmail、学一套新流程，习惯根本养不成。发短信不用学。

他描述了一个画面：建一个群聊，成员是他、他奶奶和 AI 助手。奶奶有问题，直接在群里问，助手当场答。这种多人体验，ChatGPT 今天做不到，那些 AI 助手网站也做不到。他甚至觉得 Grok 长在 Twitter 上是有道理的，因为人们本来就在 Twitter 上扔想法。

第二个是专做模型评测（Evals）的公司。新模型一发布，用户根本不知道它对自己的场景是变好还是变坏，唯一的办法是建一套自己的评测，而今天做评测的流程痛苦得要命。他说自己没见过谁把这个问题解决好，主持人补充，大概有二三十家早期公司在做，但都没跑通。

Notion 的 Linus Lee 在另一期节目里提过一个反直觉的观点：评测工具最大的价值，恰恰是人亲眼去看模型在哪儿失败，从失败细节里学东西，把这一环自动化掉，价值也就没了。Logan 觉得有道理，边缘案例正是理解模型怎么变的最快途径。

这里还能看到 OpenAI 的产品取舍。Assistants API 被他点名为长期最重要的产品，只是普及需要时间：大家不想自己折腾 RAG 的细枝末节，想要现成的工具，代码解释器半年前还进不了 API，现在已经人人可用。九个月前他上这档节目时押注 embeddings 被低估，后来果然人人都在搭 RAG 管线，这次他押 Assistants API。

但他也承认，企业客户里有一批人对 LangChain、LlamaIndex 这类风投支撑的依赖很警惕，宁可自己重写基础设施。他的观察是，自己重写这些抽象层，工作量比想象中小得多，他自己用 API 就是这么干的。

智能体上网，还要等几年

关于智能体（Agents），Logan 的判断比半年前的市场热度冷静得多。互联网的基础设施还没准备好。区分真人和 AI 的验证机制、网站给智能体单开的通道，这些都需要按年计算的时间。

他的设想是，网站可能要给 AI 开一扇不同的门，有些信息本来就不该给智能体看。而且让智能体像人一样填验证码、跳转层层页面，本身就是对算力的浪费。什么时候能加速？他提到和前 Twitter CEO Parag Agrawal 聊过，几家大公司正在推某个开放标准，可能由苹果、谷歌这类「互联网守门人」牵头组联盟。

他否认 OpenAI 手里攥着完美的智能体产品故意不发。除了安全，还有很朴素的原因：让模型稳定可靠地上网操作，工程上就是很难，人上网还经常碰上页面不按预期工作呢。

回头看 AutoGPT、BabyAGI 那波热潮，他的评价是正面的，热潮逼着整个行业提前认真思考这些问题，包括滥用的风险。

这期节目里他最兴奋的案例是 tldraw。这个白板工具接上 OpenAI 一整套能力，用户随手画几笔，自动变成一个能用的应用。他当时就坐在台下，看 Greg Brockman 在三月的 GPT-4 发布会上演示画草图生成网页。一年后，一个开发者用几天时间把类似的东西做成了真产品，几十万上百万人用上了。用他的话说，这是「让技术触达更多人」的完美样本。

一亿周活之外，普通人怎么上车

一亿周活听起来吓人，Logan 却说这个数字放大看很小，这项技术最终会深刻影响全世界。ChatGPT 是 2023 年维基百科搜索量最高的词条，大家都在围观，但围观不等于会用。

OpenAI 内部的取舍也能解释这些坑。像按 API key 查用量这种功能，工程上不算难，但团队要拿它跟可靠性这类北极星指标交换资源。工程人手长期紧张，新能力的生产化永远排在仪表盘和告警前面。他希望 2024 年补上这些毛边，做一个真正的企业级平台。

企业还在犹豫什么？他给了两个主要理由。第一是稳定可靠，今天要上生产，得自己搭编排框架，用 Guardrails AI 这类第三方护栏工具，Dev Day 连版权赔付保护（Copyright Shield）都推出了。第二是延迟，很多场景等不了七秒。他引过一句话，LLM 像人类思维的克隆，却跑不出思维的速度，这种错位感很伤体验。他希望到 2024 年底没人再拿延迟说事，前提是英伟达继续给力。

他住在芝加哥，刻意待在硅谷泡沫外面，身边大多数人的反应是：不知道这东西对日常生活有什么用。他的药方分两步。第一步，写下自己最讨厌做的五件事，再写下最想擅长的五件事，然后逐个拿 AI 去试。第二步，把它变成习惯，遇到问题先打开这些工具，才能看见这项技术会把自己带向哪里。

对开发者他的话说得更重：今天还有程序员既不用 ChatGPT 也不用 GitHub Copilot，他觉得难以置信。一个普通开发者加上 AI，能赢过没有 AI 的顶尖开发者。

至于谁来把普通人领进门，他押注苹果。十亿用户锁在苹果的体验里，等 Siri 真正变得有用，大量人的兴趣会被点燃。录制当天早上，谷歌 Gemini 刚刚发布，他的态度是大方乐见：谷歌能做出这个量级的东西很不容易，他最关心的问题很实际，会不会有人真用他们的 API，会不会有人真用 Bard。竞争最终受益的是他这样的 Gmail、Docs、搜索用户。

团队的变化他也没回避。入职时整个 API 的工程只有六七个人在做，如今细分出能力、微调、企业产品好几个团队。Sam Altman 那场董事会风波，他给出的评价是个意外的收获：把扩张太快差点散掉的团队重新拧紧了。

这期节目信息很密，挑几条明天就能照做的：

  • 做一次自我审计：列出最讨厌做的五件事和最想擅长的五件事，逐个丢给 ChatGPT 试一周，别再问「AI 能帮我什么」，先从自己的问题出发。
  • 记住三四条指令这条线：提示词简单就用 3.5，指令一多直接上 GPT-4，Dev Day 降价后多数场景不值得为省钱折腾。
  • 重度用函数调用的话，试试微调：把函数定义从提示词里微调出去，每次请求的 token 账单能砍掉一大块。
  • 上生产环境先搭可观测性：自建或用现成工具都行，看不清请求日志的 API 使用，出问题是必然的。
  • 建一套自己的评测：新模型发布别急着换，先跑一遍自己的测试集，看失败案例比看演示有用。

最后用 Logan 的一句话收尾，他说这些工具给了他一种两年前没有的自由：脑子里能想到的任何东西，都敢动手去做。这个判断，值得每个还在观望的人验证一次。
