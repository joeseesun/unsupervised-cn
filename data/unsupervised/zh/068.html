《OpenAI GPT-4.1 负责人：评测保质期只有三个月，模型进度全停也够创业者干十年》

一个模型项目，头三个月一个模型都没训。这是 OpenAI GPT-4.1 后训练负责人 Michelle Pokrass，在红点创投 Jacob Efron 主持的播客 Unsupervised Learning 第 64 期里给出的研发时间线：前三个月只搭评测、找问题，中间三个月密集做训练实验，最后一个月内测、快速收反馈。一半时间花在搞清楚问题是什么上。

Pokrass 在 OpenAI 待了两年半，工程出身，之前在 Coinbase 写高频低延迟交易系统。她先做 API 工程，因为总听到开发者想要结构化输出这类能力，转去做模型研究，现在带一支「高级用户研究团队」。改名的逻辑她讲得直白：今天高级用户在干的事，一年后就是普通用户在干的事。高级用户也不只在 API 里，ChatGPT 的免费版、Plus、Pro 里都藏着一批。

2025 年 4 月发布的 GPT-4.1 一次出了三款：标准版、mini、nano，全部面向开发者，主打指令遵循、长上下文和代码，发布时几乎没吹跑分。为什么这么选，怎么做的，这期播客讲得很透。

评测的保质期，只有三个月

GPT-4.1 的目标，她概括成一句话：让开发者用起来爽。之前的模型常见毛病是基准测试很漂亮，实际一用就摔跟头，指令不跟、格式奇怪、上下文短到没法用。团队为此建了一个内部指令遵循评测，全部基于真实 API 用法，当整个项目的北极星。

怎么挑评测？实际是反过来的：开发者不会拿着一百条需求上门，只会说「这个场景有点怪」。团队的工作是追问、写 prompt、复现，把反复出现的主题变成可训练的评测。信号源有三路：外部用户的抱怨、团队自己用模型的体感、还有一堆基于 API 建产品的内部客户。她举了个例子，有用户需要模型「忽略你对世界的全部知识，只用上下文里的信息」，这种能力 MMLU、GPQA 一个都不考，但对那个用户是命门。

她还在到处收评测。OpenAI 有个评测产品，开发者主动共享评测就能换免费推理额度。她最缺两类：一是真实场景的长上下文评测，合成的只能打窄场景，整体上长上下文行不行还是缺数据；二是指令遵循，她称之为机器学习里最难定义的东西，每个人说模型没听指令时，指的其实是几百种不同的事。

内测时还有个反直觉的故事：某位 alpha 客户坚定地喜欢第一版，而不是最终发布的第四版。他是唯一一个，所有评测指标在两个版本之间都是向上的，团队查了半天没查出原因，最后发现是某个极窄的场景没被任何评测覆盖。模型不可能讨好所有人，指令遵循做好了，可以教用户写更好的 prompt，再不行还有微调兜底。

评测本身也有寿命。一个评测的保质期大约三个月，进度太快，饱和太快。SWE-bench 她认为还有用，55% 和 35% 之间的差距是惊人的，Aider 的评测也算有用；完全饱和的就该扔。用尽一个评测的价值，然后造下一个，SWE-bench 的继任者一定会出现。

三个月找问题，三个月做实验，一个月内测

三个模型里，4.1 是一次 mid-train，对现有基座做新鲜度更新；mini 和 nano 是全新预训练。她的团队负责后训练，管的是数据配比、强化学习的参数、各种奖励的权重。nano 背后有个假设：更便宜更快的模型，能不能催生更多 AI 采用？答案看来是肯定的。成本和延迟曲线上的每一个点都有需求。企业软件公司 Box 接入后做了读文档的功能，一次能读 17 页文档，CEO Aaron Levie 发推晒了成绩，核心产品提升明显。

她最期待的研究方向有两个。一是用模型改进模型，合成数据已经被证明非常有效，用模型的信号判断训练有没有跑偏，模型每强一分，下一轮改进就更容易。二是提高迭代速度，实验越多研究越多，目标是用最少的 GPU 跑实验，睡前提交任务，早上醒来就知道成没成。这里面有基础设施问题，也有机器学习问题，训练规模不够，小实验是出不来信号的。

Agent 的能力基本够了，缺的是接线和耐心

对 Agent 现状，她的判断是：Agent 在边界清晰的领域已经工作得非常好，工具齐全、用户诉求明确的场景都没问题。缺口在模糊混乱的真实世界：用户往客服框里随手打一句话，并不知道 agent 能干什么；agent 对自己的能力边界没意识；跟外部世界连接不够，缺上下文。很多能力其实已经在那了，难的是把上下文喂进模型。

待改进的还有模糊性处理：模型该追问用户，还是带着假设继续干？总是回来问「你确定吗」很烦人，这里需要更多可调控性。

她做了个很少人肯下的功夫：把外部 function calling 和 agentic 工具使用基准的失败案例逐条拆开，发现大多数是判卷判错、题目本身模糊，或者评测脚手架里的用户模型没听指令。他们很难找到模型真的做错了的案例。换句话说，大部分 agent 基准已经饱和，分数低未必是模型的锅。

长任务还差两块。工程侧，需要能看着 agent 干活、有进度摘要、能中途插手改方向的界面，Operator 有，API 还没有。模型侧，是出错时的韧劲，API 返回 500 的时候模型不能卡死，她管这个叫 grit。未来六到十二个月，会有更多工具和上下文被接上。

Deep Research 和 Operator 属于从零到一的产品，要对单一工具做深度强化学习训练。但 o3 证明了另一条路：把模型训得擅长所有工具，学会一套工具还会让别的工具用得更好，她不预期未来会做太多单工具特训。编程 agent 是最近的事，SWE-bench 的成绩已经超过很多人类；她个人认为客服这类长工作流 agent 的能力也已经在 o3 里了，o3 调用开发者指定的工具时，工具调用已经进入思维链，模型能看着上一步输出继续想，剩下的是把这些接成一个完整产品。

代码从 9% 到 2%，以及给开发者开小灶的代价

代码是 4.1 提升最大的方向之一。局部范围的代码任务，比如改一个库、几个文件挨在一起，模型已经非常好。SWE-bench 上漏掉的题，是需要全局上下文、跨多个文件推理，或者要把一个文件里的技术细节精确传到另一个文件的题。前端代码进步也大，但她的标准更高：生成的代码不光要好看，要让前端工程师为之骄傲，所以 lint 和代码风格是重点。

一个具体数字：内部评测上，「改了不该改的地方」这类无关编辑，从 GPT-4o 的 9% 降到 4.1 的 2%。但 2% 不是零，还要继续压。后训练对数据配比很敏感，如果只训一种 diff 格式，用户用别的格式模型就懵了，所以 4.1 一口气训了大约 12 种 diff 格式，目标是没读过文档的开发者开箱也能用。

两个她亲测有效的 prompt 技巧：一是把 prompt 结构化，XML 标签在 4.1 上效果特别好；二是告诉模型「继续做，别回来找我」，直到把问题解决再回来，提升幅度大得反直觉，也是他们想在下一代模型里修掉的事。

她自己写代码用 Codex，主力模型是 o4-mini，图快；GitHub Copilot 也还在用，偶尔玩 Windsurf 和 Cursor。在 ChatGPT 里她的用法是：主力 GPT-4o，写作和创意用 GPT-4.5，最难的数学用 o3，报税就是拿 o3 做的。Jacob Efron 接话说自己还不敢把报税交给模型，她回了一句：明年我一定继续这么干。

为什么给开发者单独做一个模型？她的理念是押注 AGI 里的那个 G，一个通用模型打天下，顺便简化产品线和 ChatGPT 里的模型选择器。但 4.1 是个例外：需求太急，跟 ChatGPT 解耦之后，训练反馈更快，发布时间线独立，还能砍掉 ChatGPT 专属数据、上调代码数据的权重。这种选择有代价，数据配比是零和游戏。GPT-5 真正的难题，是把聊天伙伴和深度推理合进一个模型：你说 hi 的时候，它不该思考五分钟。个性化她倒不担心，记忆已经让每个人的 ChatGPT 不一样了，她的和她妈妈的、她丈夫的已经不同，方向是让用户自己调出想要的人格。至于会不会有独立的机器人基础模型、生物基础模型，她还是押通用化，内部趋势看，把所有东西合在一起结果明显更好，机器人要等实证。

微调的复兴：从「几个月套利」到「推动前沿」

Pokrass 承认自己曾经是微调空头，觉得那不过是几个月的套利，不值当。现在改口了，因为微调分成了两个阵营。第一个阵营用 SFT 换速度：拿到 4.1 的质量，只要零头的延迟，这仍是 SFT 的主力用法。第二个阵营是 RFT，强化微调：SFT 在极窄的领域或许有点用，RFT 能在你的具体领域把前沿推出去。RFT 用的和 OpenAI 内部训模型是同一套强化学习流程，比 SFT 不容易脆，而且数据效率极高，一百个样本量级就够。这个产品下周 GA。

她的选择框架：风格问题用偏好微调；简单分类任务，比如 nano 分类错 10%，用 SFT 补齐；市面上没有任何模型能干你要的事，用 RFT。适合 RFT 的领域有个特征：需要探索，但结果容易验证，比如芯片设计、生物、药物发现，尤其适合手里有独有数据、数据又可验证的深科技公司。药物发现有个坑，验证周期可能长达十年，反馈回路里得设中间步骤。

「有些用例现在十次里成一次，你想让它成九次。把这类用例揣在兜里，新模型一发布它们直接就能跑，你就是第一个上线的。」

创业公司明天就能用的清单

企业怎么跟上一个月一个新模型的节奏？她的答案还是评测：最成功的创业公司，懂自己的用例，有好的评测，新模型发布后花一小时跑一遍就知道该不该换。这些公司还能调整 prompt 和脚手架去适配具体模型。她建议再囤一批「差一点够得着」的用例，判断标准是个启发式：如果一个任务现在通过率 10%，微调能拉到 50%，说明产品上还不可用，但正处在临界点，几个月后的新模型大概率直接碾压。

脚手架值不值得搭？值得，那是几个月的套利窗口，创业公司的本分就是先把价值送到用户手上。但要盯着趋势走：上下文窗口、推理能力、指令遵循都会持续变好，多模态是下一个，GPT-4o 里跑不通的多模态用法现在很多直接能跑。现在先搭 RAG、prompt 里把指令重复五遍（4.1 已经不用这么干），都行，但心里要有数，随时准备拆。就算今天结果已经不错，也值得把模型接到尽可能多的任务信息上，因为明天它会更好。

她最欣赏的客户，能把评测拆到子组件，说出「模型选对 SQL 表的概率提升了多少，选对列的概率下降了多少」。这种颗粒度才能定位问题。系统要做成模块化，方便随时换零件，前期费点时间，长期跑得快。选团队时她「做多通才」：看好像产品、什么都能干的工程师，胜过只有一摞论文的博士。

快问快答环节，她认为被高估的是基准测试，agentic 基准大多饱和，厂商晒的是最好成绩，真实数字另说；被低估的是用自己的真实使用数据建评测。过去一年她改变的想法还是微调，从空头转多。问到今年模型进度，她的判断是和去年差不多：没有放缓，也谈不上起飞，就是持续快，而且模型会很多。日常生活里她喜欢把 AI 带出数字世界的产品，最近在用 Levels 和 Whoop 这类健康应用。

最后是一个可以压惊的判断：模型进度就算现在全部停下，也至少够创业者干十年。她拿互联网类比，互联网的能力过剩到今天都没消化完，还在吃世界；GPT-3.5 Turbo 的能力都没被榨干，还有十亿美元量级的公司只需要那个水平。模型会继续变强，但真正的瓶颈在接线、在评测、在把上下文喂进去。

如果明天就想动手，可以照着这张清单来：

  • 给自己的产品建一套基于真实用法的评测，拆成子组件，新模型发布后花一小时跑一遍。
  • 记录那些「偶尔能做对」的用例，10% 能微调到 50% 的，留给下一代模型。
  • 微调按需选择：风格用偏好微调，简单分类用 SFT，没人能干的事用 RFT，一百个样本起步。
  • 写 prompt 用结构化格式，加上一句「继续做，别回来问我」，4.1 上效果显著。
  • 选模型的路径：从 4.1 起步，要快就 mini 和 nano 加微调，4.1 够不着上 o4-mini，再不行 o3，最后 RFT。
