《官方推特只发40条，Chroma却拿下7000个GitHub星》

一家开源数据库公司，官方推特账号总共只发过 40 条推文，GitHub 上却攒下 7000 多个星，Discord 社区里挤着 4000 个开发者。

这家公司叫 Chroma，一个开源向量数据库，到这期播客录制时才成立 14 个月。CEO 杰夫·胡伯（Jeff Huber）是个三度创业者，上一家公司 MightyHive 被 1.5 亿美元收购。Redpoint Ventures 的播客 Unsupervised Learning 请他做客，把 Chroma 从零到 7000 星的过程讲得相当坦诚，哪些靠运气，哪些靠判断，哪些纯属意外。

从150条私信开始的创业

胡伯和联合创始人之前都在应用机器学习一线干过，见过太多“性感 demo”和“能扛住生产的系统”之间的鸿沟。他的原话是，可靠性每多一个 9，难度就大一个数量级。

传统深度学习团队怎么补数据？他举了个自动驾驶的例子：停车标志检测器一被柳树遮挡就失灵，怎么办？让数据分析师去历史数据里翻出一千个类似样本，再找个仿真厂商生成一堆“柳树挡停车标志”的变体，标注，喂给模型，祈祷它变好，同时祈祷别把其他能力搞坏。这套流程今天依然是很多团队的常态，新数据进训练池靠随机采样。

胡伯当时的判断是，模型潜空间的几何结构本身，可能就是打通 demo 到生产的路径，因为那是模型自己理解数据的方式。2022 年 5 月公司成立，比 Stable Diffusion 走红和 ChatGPT 爆发都早。

真正定下方向的，是 12 月的一次笨功夫。他把当月在推特上提到过 embeddings 或 LangChain 的用户全搜了一遍，给所有开着私信的人挨个发消息。一共只有 150 来个人，最后约到 35 个 Zoom 通话。聊完确认了判断：大家要么自己造轮子，要么在用为别的场景造的工具，都很痛苦。

1 月初他给投资人发了封邮件，标题叫“帮我们穿过这片想法迷宫”，核心三句话：大模型很重要；所有数据都会被嵌入，好让语言模型读得懂；一个极度强调开发者体验的系统还不存在。

2023 年 2 月 14 日情人节，Chroma 开源发布。原计划前一天上线，因为一个 bug 推迟了一天。

给大模型装一个外接记忆

向量数据库到底解决什么问题？胡伯的解释很直白：语言模型的权重又大又贵，更新困难，而且不可控。你往训练语料里反复塞一个事实，它未必学得进去；想从权重里精确删除一条信息，今天根本做不到。

所以思路是给模型一个外部知识库：人能看进去，能增、能改、能删。删掉一份文档，模型就“不知道”这件事了，和其他数据库一样即时生效。

他喜欢用《黑客帝国》打比方：坦克给尼奥下载程序，尼奥睁眼说“我会功夫了”，直接进道馆打墨菲斯。向量数据库想让语言模型拥有的，就是这种外挂式记忆。

那嵌入（embedding）是什么？胡伯说穿了，就是一串数字，字面意义上的数字列表，有含义的是这些数字的排列方式。嵌入模型经过训练，会把相似的东西放进高维空间里相近的位置。OpenAI 的嵌入是 1536 维，每份文档就是这个空间里的一个点。

这带来一种关键词搜索给不了的模糊匹配。搜“巴黎的舒适咖啡馆”，关键词搜索只能给你含“巴黎”的文档，顶多附赠“巴黎人”之类的变体；向量搜索能把阿姆斯特丹、柏林的同类咖啡馆文档也拉到附近。

拿 ChatGPT 举例，问它巴黎的咖啡馆，模型要么吐出训练语料里的过期信息，要么干脆编一家不存在的店。向量检索的作用，是先把事实找出来，塞进提示词，再让语言模型开口。

不够聪明，反而做出了简单的东西

7000 星怎么来的？胡伯的复盘相当不装。他说时机好得离谱，大概率是运气。然后是那句被很多人引用的话：

某种意义上，我们可能是不够聪明，做不出复杂的东西，结果做出了一个简单的东西。

人们学新技术时，就想抓那个简单好上手的。Chroma 坚持约定优于配置，从官网首页到文档到 API 都追求直觉化：它做你认为它该做的事，没有暗坑。“它就是能用”这句话，做起来最难。他引了米开朗基罗那句老话：大卫像是什么？我只是把不是大卫的部分都去掉。

有意思的是，胡伯主动承认市场做得差：官方推特只发过 40 条推文，办过几次黑客松，没了。创业者天天被教育“你做了别人也不会来”，他说这条规律在他这儿错得如此彻底，连他自己都意外。

联合主持人、前 GitHub 首席运营官 Erica Brescia 补了一句：这像极了早年 MySQL 走红的路径，靠平易近人和熟悉感赢下第一批用户。

胡伯还自嘲，“产品重于分发”这话从他嘴里说出来像个黄色警报，他们其实也看重分发，只是社区把产品磨得更快：用户找到毛边，告诉他们，他们修。开源公司真正的护城河，是那群愿意给你挑毛病的人。

至于路线图，Chroma 发布以来 API 表面几乎没动过，但用户拿它搭出了团队没想到的东西。胡伯说，好的抽象是软件里最难找到的东西，他们可能碰巧找到了一个。他反复讲一条主线：从 demo 到生产。今天 Chroma 把 demo 和小型生产场景服务得不错，大型生产场景还没服务好，低运维负担的生产环境也没有，因为托管服务还没上线。下一步两件事：发布开源的分布式版本，依然是 Apache 2.0 协议；再基于它做托管服务，先提供无服务器的向量检索体验。目标是开发者在一个 Jupyter notebook 里学会的那套 API，能一路带进生产环境，撑起千万级用户。用他的话说，他们有机会参与定义新一代软件如何被构建、如何运转，这种机会人一辈子碰不上几次。

大厂都加向量功能，怕不怕

播客里绕不开的问题：Postgres 有 pgvector，MongoDB Atlas 加了相似度搜索，Redis 也加了，专用向量数据库还有活路吗？

胡伯的态度是欢迎，这些动作在帮全行业科普这项技术。但他话锋一转：为了勾选框合规往现有产品上贴功能，做不出最好的开发者体验。最好的体验需要极端的偏执，需要一个把全部心思押在这件事上的产品。开源世界还有另一条规律：每一类软件最终只有一个项目跑赢，赢下社区的爱，那才是最重要的。他打了个比方：谁都能给马装个马鞍，自称赛马入场，但赛道跑着跑着，谁真行就看得出来了。

关于向量数据和传统数据库的差别，他有个技术判断值得记下来。关系型数据库的优势是数据天生二维，行和列，做成表格放上屏幕，人一眼看懂；数据一旦超过四个维度，人类就基本没辙了，1536 维更是如此。所以除了事务型的基本功（ACID、低延迟、高召回，这些是入场筹码，做起来不容易但必须做），更有意思的问题是怎么帮开发者和语言模型本身去观察、解释潜空间，那更像分析型负载。他的暴论是：向量可能是第一种让 HTAP（混合事务与分析处理）真正成立的数据结构，单条记录的读写和全库的分析，也许终于能在一个系统里都做好。

四个没人答得了的问题

播客录制前一周，Chroma 刚宣布组建一个小的应用研究团队，研究大语言模型领域悬而未决的问题。胡伯先划清界限：他们不训练自己的语言模型，不做嵌入模型，不和 OpenAI、Anthropic 竞争，在所有模型供应商面前保持瑞士式中立，这样才能向用户保证推荐不带私心。

但开发者哪怕做最基础的用例，也会一头撞上四个问题：

  • 文档该怎么切块（chunk）再去嵌入？
  • 用哪个嵌入模型，还是几个一起用？
  • 检索多少个最近邻，5 个、10 个还是 15 个？
  • 检索回来的结果到底相不相关，是不是落在了太稀疏或太稠密的区域？两种情况都是失败模式。

评估更是重灾区，连一个大家公认的评估方法都还没有。选嵌入模型，理论上该看评估指标，可指标本身就没定论。

更前沿的判断有两个。一个是检索会往流水线深处走：今天是一次性检索，先查资料塞进上下文窗口，再让模型一口气生成；未来可能边生成边检索，按显著性指标逐 token 取资料。

另一个是胡伯引用 Sam Altman 和 Patrick Collison 对谈里的说法：开源模型会接手 GPT-3.5 级别的常规摘要类工作，社区会把记忆机器蒸馏成推理机器，保留推理能力这块“前额叶”，模型更小、更便宜、更好微调，也更可控，因为事实性的部分交给外部检索来供。他说社区已经在这么干了，Alpaca、LoRA 这些项目就是例子。

开源和闭源模型怎么选？他的类比是车：有时需要 2.1 秒破百的跑车，有时皮卡就够了，跑车贵得多。他还给了一组要盯住的数字：语言模型的运行成本和耗时，未来十年每三年至少降 10 倍，复利算下来，十年后是千倍。看两条曲线，成本速度曲线和能力曲线，再算不同用例的交点在哪，这是他理解这个行业的计量经济学方式。

Agent 的冷与热

眼下所有用例里，“跟文档聊天”占大头。胡伯把这比作 Web 1.0 时代把报纸搬上网：把已经在做的事用新方式再做一遍。硅谷过去 15 年每五年闹一次聊天机器人热，这轮大概率真能成，地球上每一份文档集都会长出对话能力。但它是“第一个显而易见的应用”，真正原生的应用是 Agent：让每款软件里都住着一个懂你、记得你偏好的智能。

Agent 这个词刚经历了一轮完整的过山车。胡伯的观察是，推特把炒作周期压缩到了 30 到 90 天。AutoGPT 的 GitHub 星数曲线史上罕见，然后摔得很惨，现在处于漫长的爬坡期。他的建议很干脆：崩盘恰恰意味着该开工了。

他对 Agent 的核心判断：一个 Agent 的上限取决于它的上下文。调教语言模型与其说像工程，不如说像园艺，土壤好不好，水给够没有，光照过不过量，更像做饭而不是烤面包，有大量手艺成分。

他举了个所有人都觉得显而易见的例子：邮箱 Agent。一个小东西住在你收件箱里，帮你处理邮件、起草回复（先不替你发送），记住你的指令，接受“下次别这样”的反馈，从你的数据尾气里学你的习惯、语气和调性。听起来理所当然，但今天跑一个这样的 Agent，普通用户每月可能要花几百美元，太贵。等模型更便宜、能在手机和笔记本本地跑，这类东西会铺开。

一个 Agent 还是多个 Agent？他站队很明确：

我坚定地站在多 Agent 阵营。更小、更有主见的 Agent，彼此协作解决问题。“一个 Agent 统治一切”至少在短期是个傻事。

理由还是上下文：上下文可以住在共享的花园里，换个 Agent 进来，照样享受土壤、水和阳光。传统深度学习的老教训也适用：让模型做尽可能小的事，可靠性最高，然后在外面围好护栏。大模型是能力跃迁，但消费级体验要的可靠性，大概率还是得靠小模型加护栏。

多模态、长上下文与“第0天”

多模态嵌入是胡伯觉得“很酷也很疯狂”的方向。最简单的版本：搜“巴黎的舒适咖啡馆”，返回的是照片，因为文本和图像在语义空间里本来就挨着。更疯的版本：给一段 Led Zeppelin 的歌，找出与之相关的 SQL 查询。他自己都说，不清楚有没有用，但真的很酷，像给语言模型装了联觉，听到颜色，尝到声音。

还有一个被他判定为“迟早人人都要做”的动作：在嵌入空间上做微调。通用嵌入空间是用互联网数据训练的，你的数据它没见过。假如你的数据全是医疗数据，它们大概率挤在嵌入空间很小的一块区域。解决办法是给一个小神经网络，甚至只是一个线性变换，反复反馈“这是好匹配，这是坏匹配”，让整个空间平移、剪切、拉伸，贴合你的业务。今天大家还惊叹于几个积木拼出来的魔法，等哪天被追问“为什么两成的情况不工作”，这些生产化动作就会变成标配。

他还泼了盆冷水：风投圈和软件圈高估了语言模型，因为大家都是整天跟文字打交道的“文字生物”，双手整天悬在键盘上。他拿乐高说明书举例子：陪四岁孩子拼乐高时他意识到，GPT-4 大概率拼不出一份乐高说明书，顶多两岁小孩水平。视觉嵌入加上视觉 Transformer，才能让这些能力走进物理世界，前提是只用在好的地方，别整出灰胶或回形针最大化那种科幻灾难。

快问快答环节，他认为被高估的是长上下文窗口：大多数任务用不着那么长的上下文，长上下文不免费，更慢更贵，而且已有研究显示注意力在长上下文上的扩展本身就可疑。它降低了实验门槛，这是好事，但远非推特上吹的万能药。被低估的是 Agent，他觉得现在可能正处在 Agent 炒作周期的谷底。Erica Brescia 当场吐槽：风投圈可不这么觉得。

聊到监管，他的态度是：恐惧驱动的仓促立法容易带来意外后果，宁可别太早。他拿核弹监管的老案例对照：铀离心机的能耗藏不住，全球可侦测，所以当年管得住；今天有人想用算力密度做类似类比，可“模型更大就更危险”这条推理链，用最近三十天的事实去更新，已经没那么显然了。他还提醒一种每个时代都有的心态：总觉得自己这代人既是最棒的、也可能是最后一代。七十年代人们担心的是饥荒和全球变冷，这种末世感会让人以拯救文明的名义做出糟糕决定。

主持人问 AI 未来会怎么演化，他笑说，十年期的预测可以做，一个月的预测也可以做，两三年的预测最要命，因为所有人都会错。

节目的最后一个问题，胡伯自问自答：现在学这些东西太晚了吗？

他的答案是，现在还是第 0 天。创业不晚，读博不晚，进 OpenAI 不晚，进 Chroma 也不晚。

给想在明天就动手的人，这期播客至少留下四件能直接做的事：

  • 做检索增强生成（RAG）应用之前，先回答那四个问题：怎么切块、用哪个嵌入模型、取几个近邻、怎么评估。答不上来，就先把评估标准定出来再写代码。
  • 在自己的数据上试一次嵌入空间微调：标注几十对“好匹配、坏匹配”，用一个线性变换把通用嵌入空间拉向自己的领域。
  • 别无脑堆长上下文。先把上下文当成本核算，该检索的检索，该裁剪的裁剪。
  • 把 pip install chromadb 敲进终端，十几分钟在笔记本上跑通第一个向量检索，亲身感受一下他们说的“约定优于配置”。

用胡伯的话收尾：炒作崩盘的地方，就是该开工的地方。
