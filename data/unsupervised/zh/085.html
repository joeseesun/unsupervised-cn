《OpenAI企业产品负责人：模型热插拔时代结束了，200家企业趟出来的三条军规》

GPT-5 Pro 花 30 分钟，复现了一篇刚发表的黑洞物理论文里的数学推导。论文不在任何训练集里，等于现场考试。论文作者自己估算，这活儿交给职业物理学家，得干上几个星期。

讲这件事的人叫 Olivier Godement，OpenAI 企业产品负责人。过去两年多，他跟 200 多家企业打过交道，T-Mobile、安进、纽约梅隆银行、Salesforce、Databricks 都在名单上。最近他上了 Redpoint Ventures 投资人 Jacob Efron 的播客 Unsupervised Learning，从 GPT-5.1 的迭代逻辑聊到企业用 AI 的门道，干货密度很高。挑重点说。

内部数据：Codex 让工程师多提交了 70% 的 PR

GPT-5.1 和 GPT-5.1 Codex 是上周刚发的模型。Godement 复盘了 GPT-5 的用户反馈：智力、指令遵循、流式输出都受欢迎，槽点是慢，简单问题也要想半天。所以 5.1 的核心设计目标就一条：保住智力，压缩思考 token，把速度提上去。现在用户在简单问题上用低思考档，复杂问题切高思考档，来回切换很顺。

Codex 是 OpenAI 内部用得最狠的模型，公司里每个工程师、每个研究员都用过或正在用。最新内部数据：因为用 Codex，团队工程师提交的 PR 数量多了大约 70%。它已经是内部工具栈的标配。

真正让他意外的是科学圈。过去几个月，越来越多科学家用 GPT-5 和 5.1 干本职工作：压缩整合文献、检验假设。OpenAI 首席研究官 Mark Chen 跟一位研究黑洞的物理学家合作，对方出了道难题：拿一篇刚发表的论文，让模型复现其中的数学推导，GPT-5 Pro 用了约 30 分钟完成，论文作者确认这本来是职业物理学家几周的工作量。

「加速科研是这家公司一直的目标。过去几个月，我第一次感觉这事真的在发生。」

快问快答环节，他把「科学与发现」列为整个 AI 行业最被低估的方向：做软件的人对这种场景不敏感，但科学发现是所有进步的地基。哪怕只把发现速度加快 5%，对整个经济和技术的连锁反应都是天文数字。要真做好生物模型，还得有实验室和实验反馈闭环，难，但复利最高。

Karpathy 说还要十年，他的回应分两层

Andrej Karpathy 前阵子在 Dwarkesh 的播客上说，行业把当下的 AI 吹过头了，不少产出就是 slop（垃圾内容），AI 要真正自动化整个职业，至少还得十年。Godement 每天看模型的短板，他的回应分两层。

第一层，他承认做好 agent 很难，远没到「一天自动化一个岗位」的地步。第二层，几个具体领域已经出现强自动化。编程首当其冲：

「现在要是把 AI 编程工具从软件工程师手里收走，他们大概会造反。」

客服也一样。他跟 T-Mobile 合作改善客户服务，已经在有意义的规模上做到了不错的质量。他的配方很清楚：好模型只是起点，上面还要搭 harness（把模型接到工具上的骨架层）、严谨的评测框架，再加一个人在环的飞轮持续改进。工作量大，但他的判断是：未来一两年，能被可靠自动化的任务量会让所有人吃惊。

他下一个押注的是生命科学。安进的业务本质是设计新药，这事分两大块：真正的研发实验，和行政流程。后一块大得惊人，从锁定一个药的配方到上市，动辄数月甚至数年，全程要生成复杂的受监管文件，过委员会审查，过监管机构审查。而模型恰恰擅长这种活：整合海量结构化和非结构化数据、比对文档差异。等受监管行业解决好版本管理、审计、内部权限这套流程，采用会明显加速，结果就是更多新药上市。投资机构也类似，对冲基金和银行的本职就是实时消化海量数据再做判断，正是模型的强项。

采用曲线里还有个临界点：先锋企业先趟，一开始摇摇晃晃，脚手架搭一大堆勉强立得住；等加固到真的能跑，所有人都会跟上。到了某个点，不用这些方案反而显得不负责任。客服行业已经过了这个点。

编程工具的企业采用也在提速。他已经看到相当一批企业认真投入，一次给几百上千个工程师开账号，放手让他们试。他的断代法：2024 年是编程之年，2025 年是企业编程之年，2026 年轮到谁？他猜是 PM。前提是模型两条腿走路：写代码更可靠，协作能力更强，合起来就是一个能跟你搭伙的多维 AI 软件工程师。

还差一步没迈过去：持续学习。他把 agent 比作新招的实习生，第一天只有学院派知识，没有实战经验，因为没人把每件事都写成文档。现在全靠 prompt 里写反馈来调教，等模型能根据人类反馈直接更新权重，编程、客服、金融会再解锁一轮。理想状态是 agent 每天早上还是那个实习生，但昨晚睡一觉变聪明了。

脚手架还是各家手艺，收敛方向已现

各行业的 harness 长得像不像？他的回答很干脆：目前相当定制化，这是个真问题。单 agent、多 agent、中间加确定性关卡，大家各种试，还没有一个跨行业通用的 agent 架构或运行时。原因给得很朴素：时间不够。他自己两年半就是缩影，第一年光顾着追增长，第二年才坐下来想什么行得通，现在才开始收敛到「栈里哪些东西标准化了能大幅加速采用」。

他的几个标准化判断值得记下：

  • 让 agent 拥有一台电脑，会成为行业标准。写脚本、扔进 shell 执行、拿回结果。编程是比软件工程更通用的底层能力，模型在这条线上进步最快，核心编程能力的每一点进步都会被放大几个数量级。他打了个比方：换一台没网络、没 shell、没 IDE 的电脑，他不算彻底没法干活，但离废掉不远。
  • MCP 已经是个好标准，数据和 API 连接这层，行业会继续向它靠拢。
  • agent 之间的通信，还没有一个真正被用起来的标准。

换模型的痛苦也在变大。Jacob 提到 Cognition 这类头部公司在 Claude Sonnet 4.5 发布后整体迁移，做了大量新增适配。Godement 说，对非平凡的用例，改一个 API 参数就把模型热插拔的日子基本结束了。各家模型的怪癖越来越明显：有的吃某类指令，有的按特定工具签名做过后训练，有的长上下文召回表现不一样，你得摸清每个模型的脾气再调 prompt 和 harness。连最成熟的创业公司都不愿频繁折腾，企业更想要可预期的节奏：大版本、清楚的变更日志、下个版本三个月后见。他感叹这是在重新发明软件部署的老规矩，每天扔给用户一个新二进制文件，用户只会说祝你好运。

这引出他两年多来最大的心得：把新模型往 API 里一扔，用户根本榨不出模型的真实能力。模型又美又怪，没有配方、没有蓝图、没有配套 harness，很难用到位。所以 OpenAI 把 Codex 的 harness 开源了，代码和工具定义都在 GitHub 上，在 Cursor 或任何 IDE 里都能用上 Codex 的完整能力。他判断模型厂商会从单纯的推理 API，进化到同时提供模型、harness 和参考界面，等于给行业一张标准蓝图。

那企业该自建还是采购？他的判断很明确：绝大多数企业会直接买 harness、买方案，例外只有一种，这个用例是企业的核心业务本身。零售商的销售、财务、IT 系统，跟买软件一个道理。人总是低估把任何事做到高质量所需的功夫，对 agent 只会更多。

至于 ChatGPT 本身的位置，他预计它不会取代所有工具，金融分析师还是整天泡在 Excel 里，但它会越来越像每天早上打开的第一个网站。他自己重度依赖 Pulse 功能，昨晚进来的邮件、今天的会议、该读的论文，一睁眼就备好了。深度工作流还是去 IDE 和表格里做，轻量动作会越来越多地直接在 ChatGPT 里完成。

成本降了两个数量级，需求还被价格卡着

过去两三年，GPT-4 级别查询的成本降了 1 到 2 个数量级，而且没牺牲利润率，靠的是压缩模型体积、更好的硬件、更高效的 GPU 组网，每一层都在优化。过去两年 OpenAI 做了几十次降价，每次降价带来的用量增长都超过价格损失。他的解读是：存在大量被成本压住的潜在需求。他举了个例子：模型明明擅长个性化和理解意图，为什么不是每个内容网站的首页都用 LLM 实时生成？答案就是成本和延迟。编程这种高杠杆场景账算得过来，把工程师生产力翻倍，每月付几百美元值；但要让每个人背后跑着 10 到 100 个并行异步 agent，全行业还得继续把每一层的成本打下来。

RFT（强化微调）是最近的热词。他的观察是采用还早，大部分市场还在追赶前沿，连 GPT-5.1 的基础能力都没用满。少数冲在前面的创新者已经在用：一家做税务会计软件的公司，模型开箱即用不够准也不够快，用几十个高质量环境和评分器做 RFT，在客户自己的金标准评测上把成绩提了 20% 到 30%，刚好跨过从「没什么用」到「真有用」的门槛。但 RFT 是重活：要建高质量环境，要保证评分器靠谱，一次强化学习任务跑几小时到几天。OpenAI 发了市面上第一个 RFT API，但他坦承这可能永远不会是大众市场，大部分企业的 RFT 用例不会是业务主体，日常自动化靠基础模型开箱就够。

开发者怎么选模型？他分三个桶：能力和行为是最大的一桶；成本和延迟第二；第三是氛围，说白了就是推特上的舆论，而且越来越重要，因为推特现在就是行业评测。Gemini 3 发布，跑分看着都不错，大家还是要看推特上怎么说。他笑称这是在重新发明 Gartner：你没法对比世界上所有会计软件，总得信点什么。学术基准给的信号有限，SWE-bench 和 MMLU 对客服 agent 参考价值不大，行业级基准在补位，比如服务行业的 Tau-bench，OpenAI 几个月前也发了 GDPval，专门测真实经济任务。创业公司等不起基准成熟，所以大量靠定性测试，他甚至见到一批对模型细微差异有「品味」的人，像好作家好画家一样说不出框架，但手感是真的。

200 家企业换来的三条军规

快问快答里，他承认自己一年内最大的转变：曾经相信「模型就是一切」，现在不信了。harness 重要到跟模型难分彼此，最好的 agent 都是针对特定 harness 训练的，Codex 之所以强就是这个原因；企业侧还缺一套把正确数据在正确时机喂给模型的标准基础设施。三件事缺一不可。

具体到给企业的建议，他的清单很实在。

第一条，数据一团糟就什么都做不成。老生常谈，但依然排第一。再强的编程 agent，接不上正确的代码库、身份权限、数据库，就是废物。大量工作在数据工程本身：怎么组织数据、怎么起服务、用不用 MCP、请求怎么鉴权怎么记日志。

第二条，把评测当命根子。OpenAI 内部训练模型的团队很重要，但全职做模型评测的团队同样重要。企业要文档化金标准集、写清标准操作流程、建严谨的评测。最常见的错误是评测太少或太多：只建五套评测集，第一个真实客户进来就完全出分布，什么都学不到。

这里藏着他在企业服务中发现的最大秘密：大部分知识在人脑子里。你以为是去翻 Confluence 里的流程文档，现实是能找到 20% 到 30% 已写成文档的流程就烧高香了，剩下全靠「这事 Sarah 和 Mark 最熟，你问他们」。所以建评测的核心工作是把对的人找出来，把脑子里的东西挖出来，而且是个迭代过程：先上线，发现不对，再去找 John 问为什么，再补评测。

第三条，变革管理，怎么强调都不过分。这技术对所有人都是新的，有时候强得让人发毛，有时候又不直觉到让人抓狂，花时间给团队讲清楚它怎么运作，是关键动作。

被问到 OpenAI 这两年半搞砸过什么，他也没回避：2023 年对 agent 的定义太早，产品没起量，只能下线一批 API；投了不少音频技术，最后没成。他自嘲世界对先行者宽容，历史只记住成功，中间的失败试验一大把。

顺带两个前沿信号。语音还没过图灵测试，打断和节奏差口气，但 GPT-4o 表达和理解情绪那一刻，是他心中仅次于 ChatGPT 的 AGI 时刻，一线客服已开始规模部署，模型无限耐心，还能覆盖小语种长尾，这对美国零售商是刚需，过去只能眼睁睁丢客户。Sora API 则在广告内容生成和影视工作室两头起量，导演 30 秒就能把脑子里的画面给团队看，不过视频生成还贵还慢，处于早期。

明天就能用的五件事

听完这期，能直接抄的作业有这几条。

  • 换模型别热插拔。留出专门时间做实战测试，用自己业务的金标准集跑，别只看跑分和推特风向。
  • 评测先找人再找文档。公司里那个什么都懂的人，价值超过 Confluence 里那两三成文档化率的存量流程。上生产前，评测集至少别少于五套。
  • 数据管道先行。agent 接不上代码库、权限和数据库，一切白搭，这部分是脏活但绕不过去。
  • 自建还是采购想清楚。核心业务用例值得自建 harness，其余一律买，别低估把东西做到高质量的代价。
  • 不满意就直接反馈。模型厂商控制着后训练，带着具体案例去提需求，下个版本快照里真会改。Godement 说他在推特上回复每一条反馈。

最后附赠他个人测新模型的三板斧：先测风格和语气，倒一堆上下文进去问私人问题；再让它从零生成一个应用，看前端；最后倒几十万 token 进去，专问倒数第二个 token 附近的难题。下次新模型发布，你也有自己的测法了。
