《18 个人撑起最火的 AI 框架，LangChain CEO 谈评估、Agent 和 2024》

LangChain 的 Discord 社区有 3.8 万名开发者，Elastic、Dropbox、Snowflake 都在用它，而维护这套框架的公司，只有 18 个人。

2024 年 2 月，LangChain 创始人兼 CEO Harrison Chase 上了 Redpoint 的播客 Unsupervised Learning,和主持人 Jacob Effron 聊了一个多小时。他坐在 AI 开发者生态的正中心，每天和大量团队聊怎么把 LLM 应用做进生产环境，聊出来的东西比多数报告都实在。

他反复强调，自己唯一有信心预测的事，是没人能预测 AI 接下来会发生什么。但正因为看得多，他讲了一堆一线团队踩坑之后的真实做法，还有几个和主流叙事唱反调的判断。

先交代背景。Chase 之前在 MLOps 公司 Robust Intelligence 工作，最早靠体育数据分析入坑 AI。LangChain 项目 2022 年 10 月开源，公司 2023 年成立，一年多就长成了 LLM 应用开发的事实标准。他刚启动这个项目时，推特上只有 200 个粉丝。

体育那点老本行他也没丢。他最想看到的 LLM 应用是自动生成比赛解说，还能按观众个人化，比如你上周刚看过某个球员的绝杀，解说就会提到这层关联。有个 NBA 球队找他们聊过，用途是内部数据查询，离消费级产品还远。

LangChain 到底在做什么

很多人对 LangChain 的印象停留在「帮你调 API 的库」，实际盘子大得多。Chase 给的定义是：把 LLM 连接到外部的数据源和计算上。语言模型本身够通用，框架自然也是横向的。

最常见的用法是对着自己的数据聊天，所以流式输出、检索这些功能占了大头。企业侧还有个大场景是信息抽取，再加上 text-to-SQL、调用任意 API 这类需求。

团队从第一天起聚焦三块：检索、Agent、评估。Chase 认为三者之间有个飞轮。检索领域最新的技术本身就很 Agent 化，比如 Self-RAG 和 Corrective RAG,思路都是先检索一步，自查质量够不够，不够就纠正重来。检索又是给 Agent 的最流行工具。评估两边都需要，而 Agent 反过来还能帮忙做评估。有人劝他砍掉几条线只留一个，他的回应是，语言模型的价值恰恰在通用性，这三样是几乎所有应用的地基，真要砍，他不知道砍哪个。

产品矩阵大概是这样：

  • 开源框架本体：编排层。2024 年 1 月发了 0.1 稳定版，特意等到多模态出来之后才定稿，就怕抽象层被新变化推翻重来。
  • LangSmith:独立的 SaaS 平台，做可观测性、测试和评估，和这期播客同步正式开放(GA)。Chase 的原话是，某些意义上它比 LangChain 本身做得还好。
  • LangServe:部署工具，包了一层 FastAPI,还能一键起一个 playground,让 PM 和领域专家这些非技术同事直接上手试、给反馈。他观察到做这类应用天然是跨职能的事，领域专家往往是最会挑毛病的人。
  • LangGraph:把 Agent 建成图和状态机的框架，后面细说。

LangServe 出得晚，他解释说，创业时第一个想到的生意其实是托管部署，但他们观察到可观测性和测试是更大的痛点，就先做了 LangSmith,后来看到大家真要进生产环境了才补上部署这块。

18 个人怎么分？一半做 LangSmith,一半做开源和探索项目，LangGraph、OpenGPTs 都是从探索里长出来的。优先级跟着价值走：去年秋天大家普遍卡在编排层的可组合性，团队就集中火力做了 LangChain 表达式语言(LCEL);现在底座稳了，又转头补用例文档和模板。

评估的现状：先手标 20 条，再靠人眼

评估(eval)是这期播客信息量最大的部分。Chase 把团队们正在纠结的事拆成了四步。

第一步，测试集从哪来。主流做法是先手工标注 20 条左右的例子，再把生产环境里失败的 case 拉进来。用户点了踩的、被其他机制标记的失败记录，直接进测试集。LangSmith 特意做了这条通路：线上 trace 一键转评估样本。

第二步，单条数据怎么打分。能分类的任务用传统 ML 指标就行，剩下的靠「用 LLM 当裁判」。这个技术正在流行，但 Chase 强调它并不完美，得有人工兜底。实际上，很多团队到今天仍然是人肉看结果、数一数、左右对比。

第三步，指标怎么汇总。看场景：有些关键任务要求百分之百准确，有些只需要知道这一版比上一版提示词好还是差。

第四步，多久跑一次。评估又贵又慢还容易出错，所以大家基本只在发版前跑。理想状态是像单元测试一样进 CI 持续跑，Chase 明说现在还做不到，整个行业都在往那个方向推。

聊到这里，他提到当天刚和一位叫 Linus 的朋友聊过，对方的观点是「看数据这件事被低估了」，他完全同意：

有人觉得人肉看数据点有点丢人，都什么年代了还没有全自动评估。但这个领域太早期了，看数据除了知道这一条跑得怎么样，还能让你真正理解系统的行为。这些新东西，所有人都还在学着怎么搞明白。

所以 LangSmith 重金投入了展示 Agent 思考过程、每一步输入输出的功能，就是为了让开发者更容易看懂系统。接上 trace 几秒钟就能看到价值，评估则要用户自己攒数据集、定指标，负担重得多，这也是他们持续打磨人机协作界面的原因。

他给开发者的建议很明确：构建评估集本身就是最好的思考工具。传统 ML 时代，建模之前必须先有数据集；LLM 时代这个门槛没了，想到什么直接扔给模型就能跑。但系统到底该做什么、该处理哪些边界情况、用户会怎么交互，这些问题还是得回答。攒评估集，就是逼自己回答它们的最有效手段。

各家攒的测试集能不能共享？他的观察是，数据集注定是各家自己的，认真做应用绕不开；能沉淀的是通用经验，比如 RAG 那几种常见失败模式，社区里已有讨论，但他们做得还不够，应该更好地组织大家交流。顺带一提 LangSmith 的设计哲学：代码优先，不绑定框架，用不用 LangChain 都行；被测系统在他们眼里就是一个函数，内部调了几次 LLM 一概不假设。

Agent 退潮之后，状态机接棒

他先澄清了一个误会：大家总把 LangChain 当 Agent 框架，其实他们从第一天就在做 Agent 相关的事，只是从来没 all in 那种完全自治的形态。

2023 年上半年，Agent 这个词被 AutoGPT 点燃，大家幻想着一个能自己规划、自己执行、自己纠错的通用智能体。Chase 的评价很直接：通用自治 Agent 已经完整走完了一轮炒作周期。到去年夏末秋初，大家基本达成共识：你真正想要的，是一个定制提示词、五六个工具、盯着一个明确目标的聚焦型 Agent。

那后来火起来的多智能体框架(AutoGen、CrewAI)算什么？质疑的声音一直有：一个 AutoGPT 都跑不好，五个捆一起就能行了？Chase 的解释是，这些框架的本质其实是受控的流程编排，也就是状态机：特定的提示词配上特定的工具，在定义好的路径之间跳转。

LangGraph 就是把这套思路产品化：把 Agent 建成图，或者说状态机，开发者可以控制状态之间的跳转条件。他举了个客服机器人的例子：对话开始时用一个专门收集姓名和账号 ID 的提示词，收集齐了就跳到「排查问题」状态，换一套提示词和工具继续。

他看到的生产环境里开始变得可靠的东西，基本都是这种状态机形态。而且他不认为模型变强会淘汰它：有些应用的指令本身就极长极复杂，甚至要对指令本身做检索，不同状态查不同的库。更重要的是，状态机是个好的心智模型，AutoGen 火起来靠的就是这个。

2024 的应用：复杂聊天机器人、长任务和个人化

Chase 把建造者分成三类。第一类是 AI 原生创业公司，动作最激进，直接做面向消费者的 Agent,但都太早期，还看不出成色。第二类是数字原生公司，去年主要在发单次 LLM 调用的功能，现在开始上强度了：他点名 Notion 的问答功能，认为那是规模化、个人化的知识库问答里做得最好的；还有 Elastic 已经跑在生产环境的 AI 助手。

第三类大型企业反而最容易被外界忽略，因为它们做的事大多不对外。企业内部的风险容忍度比外人想象的高:很多公司在搭类似 GPT 商店的内部平台，接自己的数据和 API,让员工自己造聊天机器人，LangChain 的开源项目 OpenGPTs 就被一些企业这么用。播客结尾的圆桌里，Redpoint 的投资人补了个细节：某全球前五大银行的合规负责人说，他们至少一年到一年半内不敢对用户开放，只想做第三个敢上线的银行。

对 2024 年，他给了两个具体预测。一是复杂聊天机器人会变多，以状态机形态出现，比如分阶段的客服机器人、分阶段的 AI 心理咨询师。二是长时任务会出现，GPT Researcher、GPT Newsletter 这类项目跑一两分钟，产出研究报告或新闻通讯的初稿。挑战在 UX:得找到用户不要求即时响应的场景，而眼下最有意思的创新空间恰恰就是 UX。

他举了个让他眼前一亮的例子：有人做了个 AI 原生表格，填好列名，像用 Excel 一样拖拽，每个单元格单独起一个 Agent 去填，上百个 Agent 并行跑，过几秒回来检查结果就好。这和聊天的一问一答完全是两种交互范式。

成本问题躲不开。他承认这种玩法今天没法规模化，但给创业者的建议是别先操心成本：先用 GPT-4 把产品做出来，有了产品市场契合度再优化。他引用了 Dust 创始人 Stanislas Polu 的那句话：「No GPUs before PMF」。

整期播客里他最上头的话题是个人化。他的判断是：现在还是 AI 应用的第一波，类似 iPhone 上市后大家还没找到杀手级应用的那段时期。Redpoint 的投资人在结尾补充，互联网和 iPhone 的杀手级应用大多出现在平台发布四五年后，Uber、Snapchat 都是这样，AI 的节奏大概率更快。用户级别的个人化，可能就是第二波应用缺失的那块拼图。Redpoint 还提到 Perplexity CEO Aravind 的长期愿景也是这个方向：同一个问题，给不同的人渲染不同的答案页面。基础设施侧他看好 Fireworks、Together 这类开源模型托管和微调平台，还有本地运行的 Ollama;应用侧他点名了做记忆的 New Computer(创始人 Sam Whitmore)和做关系管理的 Hearth AI。

如果当初没出来创业，他会去做什么？一个会记住你的日记应用。他的逻辑是，让 AI 记住你的难点在于判断什么值得记，随便聊天里大部分是废话；日记里全是高浓度的个人信息，天然解决了筛选问题。写完日记，AI 结合历史记忆跟你聊。Character AI 用户最大的抱怨，恰恰是它不记得你是谁。他说这个 demo 可能真会做出来。

反共识判断：多模态被高估，few-shot 被低估

快问快答环节，他的两个答案都很鲜明。

被高估的是多模态。模型的空间感知能力还不够，做不了大家想要的精确知识工作,比如从文档里做精细抽取。播客录制的第二天 Gemini Ultra 就发布了，他的态度是：我们不会都活在 Google 演示视频的世界里。

被低估的是 few-shot 提示。聊得多的成功团队都在用，用的人还不够多。LangChain 里有个被他点名「被严重低估」的功能叫 example selector:与其在提示词里写死三个例子，不如动态挑出和当前问题最相似的三条。他还有个更进一步的设想，称之为通往持续学习的路径：用户反馈攒到一定程度，就能攒出一个两三百条的 few-shot 案例库，每次动态选最近、最相关的塞进提示词，应用就用一种极轻量的方式持续变好。

他也坦白了自己看走眼的地方。一是流式输出，早期框架里的流式支持是打补丁式的，联合创始人 Nuno Campos 力主把它做成一等公民，后来 LCEL 从设计上就是流式优先，现在看这个决定极其正确。二是 OpenGPTs,OpenAI 开发者大会前的周末泄露了消息，他给 Nuno 发消息说要不要开源复刻一个，第二天就发了，反响远超预期。他复盘出两个原因：企业比他想的更在意对系统的控制权；LangChain 能做的事太多，他们一直没教大家怎么玩出花活，OpenGPTs 恰好是个现成的示范。

哪些东西会被模型进步淘汰？他的清单：上下文窗口变大后，对话历史的摘要压缩这类技巧会消失，大部分历史直接塞进去就行；检索不会消失；状态机不会消失；该消失的是求着模型输出 JSON 的日子，他引用了社区那个梗，「写不出 JSON 小狗就要死了」这类提示词，希望早点进博物馆。

开源模型会比现在更普及，但眼下真正有意思的东西大家还是在用 OpenAI。他更期待本地模型成熟后的那批应用：个人文档问答、私人教练人设这类，用户希望数据留在自己电脑上，桌面端本地跑的 AI 应用会是个方向。

竞争这块他也很松弛。Datadog 在 LangSmith 之前出了 LLM 观测产品，还做了 LangChain 集成，结果有些公司两个一起用，因为价值点不同：Datadog 强在系统级监控和延迟这类聚合指标，LangSmith 解决的是看不懂应用在干什么、没法放心快速迭代。他的态度是市场太早期，大概八成该做的事还没人知道是什么，不值得盯着对手。

明天就能用上的几件事

最后收个尾，这期播客里明天就能上手的东西：

  • 今天就攒评估集：手标 20 条例子，再把线上失败的 case(用户点踩的)拉进测试集，这是他看到的所有团队验证有效的起手式。
  • 别追求全自动评估，先人眼看数据。这个阶段，理解模型行为比省人力值钱。
  • 写提示词时加 few-shot 例子，试试动态挑选相似例子，别写死三条。
  • 设计复杂 Agent 时，直接按状态机来：每个状态一个专属提示词和工具集，明确跳转条件，LangGraph 是现成工具。
  • 先用最好的模型把产品做出来，产品市场契合度之前不优化推理成本。

想追进度的，他给了三个入口：blog.langchain.dev 的博客、他们的 YouTube 频道(在做 RAG 概念讲解和从零构建应用两个系列)，还有推特。

Chase 在播客里反复说的一句话，值得放在最后：别管 RAG 是不是 hack,别管这套东西半年后还在不在，先把它建出来。模型会变，工具会变，但只有真做了、真看了数据，你才知道客户要什么。
