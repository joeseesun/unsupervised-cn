《SWE-bench 80.9% 之后，Anthropic 产品负责人把 Opus 4.5 这笔账算透了》

感恩节前一天，Anthropic 没发预热海报，也没搞「猜猜明天是什么」的悬念推文，直接放出了 Opus 4.5。SWE-bench Verified 上 80.9% 的成绩，连他们自己的研究产品负责人 Dianne Na Penn 都评价：这类基准已经饱和了。

Redpoint Ventures 的 Jacob Effron 在《Unsupervised Learning》第 77 期里和她聊了一个多小时。Diane（大家习惯这么叫她）在 Anthropic 待了两年半，入职时全公司大约 150 人，如今她的头衔是研究产品负责人，管的是模型能力和产品之间的那道桥。

先放几个这期节目里的硬数字：一家做 Excel 智能体的公司 Shortcut，没动 harness，没做其他配套改动，只把底层模型换成 Opus 4.5，客户反馈准确率涨了 20% 左右；Diane 说 effort 参数被严重低估，用它能以零头价格拿到 Sonnet 4.5 级别的智能；她还判断，我们离「变革性 AI」的距离，比自己年初想的更近。

下面把这一集拆开讲。

像做产品一样做模型

很多人以为前沿实验室造模型是纯研究驱动，Diane 给出的画面意外地熟悉：愿景文档、PRD、evals，一套传统产品经理的流程。

Anthropic 内部有一份跨度很长的能力路线图：更强的指令遵循、更强的编程、更好的记忆。每一代 Claude 是这些能力的「载体」。设计新版本时，先想清楚这一代要交付哪些进步，再决定怎么打包、怎么定位、怎么定价。

立项的判断分两条线。一条是自上而下的：团队对这项技术能做什么有很强的整体判断，比如认定它会在工程等领域带来变革。另一条是自下而上的意外。今年早些时候，团队只花了一笔不大的投入，让 Claude 擅长 Excel 和 PowerPoint，结果金融服务客户反响热烈，于是决定加倍投入。用户会用真实使用告诉你哪些能力值得加注，这条路是双向的。

立项流程她也讲得很细。先像写 PRD 一样回答「这是什么、对用户有什么用、别人为什么来用」，再翻译成具体的 evals。有的方向模型已经走了一半，补补数据、做做强化学习就能到终点；有的方向得动大手术。听起来传统，但前沿实验室真就这么干活。

反馈循环如今转得很快。用 Diane 的话说，客户提的需求如果赶不上 4.5，也许就赶得上 Claude 5，你总有多次机会让自己的反馈被听见。Anthropic 还在内部建工具，自动搭建训练环境，让「客户痛点变成模型改进」这个环越转越自动。

有加注，就有放弃。图像生成、视频，客户问过，Anthropic 明确不做，资源集中砸在扩展智能上。产品侧同样聚焦商业场景：数据安全、隐私、企业级要求优先，消费级场景靠后。

最能体现这种克制的是 2023 年的一个决定。当时用户最常提的需求是「你们得有 embedding 模型，我们都在做 RAG」。Anthropic 没跟，转头押了 agentic coding。Diane 把这总结成 user-led 和 user-centric 的区别：用户提出的是当下的疼，真正的机会常常是用户还没想到要提的东西。2023 年没有客户堵在门口喊「给我们 agentic coding」，后来最大的机会就在那里。

顺带讲个彩蛋。她的团队做过 Golden Gate Claude，把可解释性研究包装成一个满嘴金门大桥的模型。当时公司不到 500 人，几个工程师、研究员、一个 PM 加一个设计师，从改模型到上线界面用了不到一天，本来预期只有几百个极客一起乐呵，结果出了圈。Diane 说这是她最自豪的时刻之一。

token 单价是个会骗人的数字

Opus 系列历来贵，Opus 4.5 又强又便宜。Diane 说，项目一开始团队就定了个目标：把效率提升传导给用户和开发者。

她特意替 effort 参数鸣不平，原话是「我觉得它现在被低估了」。调低这个参数，你可以用零头的价格拿到 Sonnet 4.5 级别的智能。

背后的观点更值钱。token 标价衡量不了完成一个任务的端到端成本。她从 builder 那里反复听到同一个故事：小模型跑一个任务，要么跑得慢，要么烧了一堆 token 还没跑成，最后总账比直接上 Opus 更贵。

Jacob 追问，市场教育怎么办？Diane 承认这是模型提供商的功课。过去一年 Anthropic 主打 Sonnet 一个旗舰，如今模型分层越来越多，教开发者按任务算账、按任务选模型，会成为他们市场投入的重点。

早期客户的数据也在支撑这个逻辑。Shortcut 换模型后准确率涨 20%，等于把智能提升直接转送给自己的用户。还有客户反馈，用 Opus 4.5 清空了积压已久的整个 bug backlog。游戏场景也被拿来做压力测试，3D 游戏生成质量明显变好，Jacob 说这已经成了大家直观感受模型智能上限的通用方式。

Computer use 和长任务：旧考卷作废了

Computer use 是 Anthropic 押了很久的方向。2024 年 10 月底，他们发布了 computer use API 的 beta 版。Diane 自己常用 Claude for Chrome 浏览器扩展，她的体感是交互质量明显变好，因为这一代模型的视觉能力上了一个台阶。有时进步就是几种能力咬合的结果，单看哪一项都不惊艳，叠起来就跨过了门槛。

她给了一条清晰的进度条：computer use 正从「agentic coding 的配角」，变成独立的端到端智能体。最早是受限环境里的 QA 测试，如今能在浏览器里当监控 agent，她个人很期待的下一步是「帮我把 Google 日历的会议改期」，这事听着简单，协调起来极其繁琐。整个方向就是从受限环境走向开放环境，离「放开整台笔记本电脑」还有距离。

聊到产品市场契合度，她的判断很直接：agentic coding 已经站住，企业客户还在持续找上门；编程之外的智能体场景有苗头，但全行业都还没找到合适的 harness 和产品形态，大量使用仍然停留在聊天框里。Opus 4.5 这一代会催生一批「主动式」体验：agent 自己出门办事，做完把结果端到你面前，省掉你打字这一步。

配合越来越长的上下文和越来越好的记忆，模型能干的事从「交付一个 MVP」扩展到「长期维护它」。发布 MVP 只是起点，长期维护才是价值所在。

长任务卡在同一张考卷上。Diane 说，行业缺的是能衡量长周期任务质量进步的 eval。现在最接近的样本有两个：让 Claude 经营自动贩卖机生意的 Vending-Bench，和 Claude 打宝可梦。

她聊宝可梦那段信息量很大。智能不只是「通关」这个勾，还包括用多少步通关。不靠暴力枚举、还记得「小智某个时间点在真新镇、已经跟某个 NPC 谈过话」的模型，才是真的变聪明了。判断力和直觉，正在变成新的测量对象。

旧考卷确实作废了。Opus 4.5 在 SWE-bench 上拿到 80.9%，Diane 原话是「饱和了」，Terminal-bench 这类基准也差不多。她记得自己去年发布工具调用 API 时，准确率还在 50% 以下。Jacob 补了一个他喜欢的例子：模型为了完成升舱任务，直接去改票的舱位类别，用绕路的办法把事情办成了。

新考卷长什么样？Diane 给了三个特征：任务开放，质量可量化，答案别只是「是或否」。她的原话：世界上大多数事情本来就不是是非题。往生物这类领域走，连 SWE-bench 的等价物都找不到，eval 设计本身就是行业级难题。

脚手架：从 20 条规矩到轻装上阵

这一段，做应用的朋友可以拿小本本记。Diane 把脚手架的进化分成两代。

2022 到 2024 年，主流脚手架是「辅助轮」，作用是把模型摁在分布之内，形态通常是 20 条规矩：别做这个，永远做那个。

今年开始，最好的脚手架变成了「智能放大器」：核心工作从约束模型变成放大模型，并且持续删掉那些不再放大智能的部分。

Claude Code 是现成例子。它的脚手架相对轻量，给模型的工具就是 bash 这类通用货，没什么特制的。目的是最大化模型干活时的自主性。她认为未来还有价值的脚手架有两类：通用工具集，以及多智能体编排。多智能体今年开始真正可行，用一组模型互相配合，放大上下文质量。

builder 们最焦虑的问题：现在这层脚手架，有多少会被下一代模型直接作废？Diane 给不出精确答案，她的建议是把 harness 做薄，越薄，换代成本越低。她还补了一个容易被忽略的变量：用户行为会推着产品变复杂。模型文档编辑能力一强，用户就敢一次丢一大包东西过去，还会要求它「另想一套方案」。脚手架要跟着用户走，光跟着模型走不够。

锯齿状的进步，和敢唱反调的模型

最近播客圈流行泼冷水。卡帕西在节目里说，真正的企业级智能体离我们可能还有十年。伊利亚·苏茨克维也在访谈里讲，当前范式只能走到这里，再往前要撞墙。

Diane 的回应分三层。

第一层，模型进步很少呈现 benchmark 上那种平滑曲线，真实形状是锯齿状的台阶。同一个版本，在你的测试集上可能只是小跳，在别人那里可能是大跳，取决于你拿什么尺子量。

第二层，客户体感是真实的。Rakuten、Lovable 这些客户反馈，能力进步确实在持续转化为团队生产力。

第三层，Anthropic 内部很少谈 AGI，谈的是「变革性 AI」。

每一代 Claude 都在真实地改变 Anthropic 员工的工作方式。如果你没有在同样的深度上采用它，可能就感受不到它在实质进步。

这句话对唱衰者和围观者都成立：进步是有的，只是它先发生在重度用户身上。

聊到安全，Diane 的视角跟大多数人相反。大家默认安全是刹车，是防止模型做坏事。她说，对齐良好的模型还有另一面。模型谄媚（sycophancy，你说什么它附和什么）目前是活跃研究领域，远没解决。而对齐做得好的模型恰恰相反，它是个独立思考者。突破和好主意来自独立思考者，安全投入实际上在放大智能的质量，远不止防坏事这一层。

她举了自己的例子。她问 Claude 定价方案，给了两个选项，模型自己冒出第三个，而且相当好，把她原本的思路都推开了。她判断，一个谄媚版的 Opus 4.5 大概率只会说「您说得对」。

时间线上她也交了底：今年她的预期提前了。看 Opus 4.5 这类模型，积木比大家以为的更齐，现在缺的更多是产品表达，能力先于产品溢出来了，她管这叫 product overhang。她自认是杠铃型：短期有很大概率，长期也有很大概率。

明天就能用的四件事

Jacob 还问了个词：model taste，模型品味。Diane 的定义：对模型能力持续打磨的直觉，愿意亲手去发现能力边界，同时理解用户想干什么。有些人拿到同样的工具，总能榨出更多东西，差别就在这。怎么练？下面四条，明天就能动手。

  • 建一个原型库。Diane 说最厉害的 builder 都留着一批「以前跑不通的原型」，每个新模型发布就拿出来重测一遍。很多能力是跑起来才发现的，没有原型，你永远只能猜「它什么时候才能做药物发现」。Anthropic 自己每三四个月办一次内部 hackathon，就是给员工一个正当理由做这种探索。
  • 按任务算成本，别按 token 算。评估模型时，把跑完一个任务的总花费算出来，包括失败重试烧掉的部分。顺手试试 effort 参数，用零头价格先拿到接近 Sonnet 4.5 的效果。
  • 给脚手架瘦身。把那些「别做这个、永远做那个」的规矩翻出来，逐条问：这条还在放大智能吗？不放大就删。工具给通用的，别给特制的，把自主性还给模型。
  • 新模型发布当天，留出改产品的时间。高级用户的共同点是愿意为新模型调整自己的产品体验，去接住智能的顺风。换一下 API key 测一遍就下结论，会错过大部分东西。

最后补一段 Diane 的职业观察，算是这期节目的底色。她入职时公司 150 人，两年前还在亲手给潜在客户发邮件、搭第一个 A/B 测试；现在三分之一时间开客户电话，其余时间带 PM、陪研究员泡在一起。她的原话：每三个月，我的工作就换一份。

公司从 150 人涨到今天，模型从「20 条规矩伺候着」走到自己会提第三个定价方案。她说 Anthropic 是她待过的最「言行一致」的公司，人才密度最高，大家彻底主人翁意识、善良但直接。至于是不是真的，至少 Opus 4.5 敢跟老板唱反调这件事，算是给了个注脚。
