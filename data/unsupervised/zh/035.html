《关键词搜索打败了向量数据库：Sourcegraph 联合创始人聊 AI 编程的一线打法》

GitHub Copilot 的付费用户已经超过 100 万，AI 编程至今仍是 AI 变现最顺滑的场景。这个赛道里有个特别的存在：Sourcegraph，2013 年成立，比那篇著名的《Attention Is All You Need》还早四年。当年去融资，投资人一听 dev tools，99% 扭头就走，最后是 Redpoint 的 Scott Raney 信了他们，这家基金早期也投中了 Heroku、Stripe 这样的开发者公司。

这期 Unsupervised Learning 播客（Redpoint 投资人 Jacob Effron 主持）的嘉宾，就是 Sourcegraph 的 CTO 兼联合创始人 Beyang Liu。他斯坦福毕业，读书时在 Daphne Koller 门下做过机器学习研究。公司有两款开发者熟悉的产品：代码搜索引擎，帮人理解庞大的代码库；AI 编程助手 Cody，做补全、对话、生成测试这些活。Cody 的差异化就一条：所有回答都建立在对客户代码库的理解上。

而支撑 Cody 长期「市面最好上下文质量」口碑的检索引擎，很长一段时间主要靠关键词搜索，外加一套聪明的代码感知分块策略。向量数据库那套时髦玩法，他们试过，结论是经常不如关键词搜索好用。

AI 编程的真实进度：内环很快，外环还没到

Beyang 把软件开发拆成两个循环。外环是从想法到上线的完整生命周期；内环是开发者每天重复几十次的动作：想清楚要做 X，找到代码里怎么改，写代码，测试，确认没问题，再做下一个 X。

他的判断很明确：今天被大规模日常使用的，只有内环加速工具，比如代码补全、理解你代码库的对话。多步骤、机器人主导的开发还没人做出来。连 Cognition 那个惊艳全场的 Devin，也得有人盯着，大部分问题仍需要人来兜底。

怎么让外环自动化？他的思路是倒推。最终产物是一个 pull request，倒数第二步是让大模型生成一次代码修改。要让这次修改靠谱，输入得有两样：从代码库抓到的上下文，加上之前所有尝试的记录，也就是一个「尝试、观察、从错误中学习」的反馈循环。

翻译成工程语言，需要两样东西：一个虚拟执行环境，让 AI 改完代码能跑、能看结果；再加足够强的上下文抓取器。如果 AI 要试一千次才能改对，时间和成本都撑不住。更好的观察、学习和检索，能把尝试次数缩短一个数量级，这是从「演示能跑」到「生产敢用」的关键。

里程碑怎么定？把所有软件问题分个类，今天能被全自动系统在生产环境解决的，是零，或者接近零。等哪天把生产日志里的报错堆栈喂给 AI，80% 的简单 bug 能自动修，那才算数。

顺带说一句，内环工具对延迟极其敏感。Beyang 至今用 Emacs 写大量代码，因为他能感觉到 VS Code 和 Emacs 的按键延迟差异，毫秒级的卡顿会消磨写代码的乐趣。这也是本地推理的机会：Cody 社区里用 Ollama、LM Studio 跑本地模型的人越来越多，第一个杀手级场景很朴实，在没网的飞机上写代码。Cody 的默认补全模型 StarCoder，本身就是开源的。

做 RAG，先从笨办法开始

这期节目对 AI 应用开发者最有价值的部分，是 Beyang 的检索方法论。他的建议简单到让人失望：做 RAG，基线从经典关键词搜索开始。容易实现，容易理解，容易迭代，你能搞明白它为什么找到这个、为什么排前面，没有黑魔法。

Sourcegraph 自己就是这么干的，而且靠这套笨办法，Cody 的上下文质量很长时间排在市面第一。与此同时，他们看着一堆同行上 embedding、上各种向量数据库，名字起得花哨，实际效果很差。团队自己也憋不住试了：把 embedding 抽出来扔进向量数据库做近邻检索，结论是比没有强，但经常不如关键词搜索。偶尔能给你惊喜，找到两个没有关键词重叠的同义概念，但噪声太大，漏掉很多显而易见的答案，还会召回一堆在向量空间里离得近、实际不相关的东西。

这套哲学来自他做研究的惨痛教训。当年在 Daphne Koller 门下，每个新研究员都想做花哨的东西，简历上好写。但正确做法是先跑基线，高斯混合模型也行，越笨越好，一天就能出结果。不然你花三个月搞个复杂模型，回头一看，还不如笨办法。

他举了个例子：前几年《自然》杂志发了一篇论文，用大型神经网络预测天气模式，风光无限。一年后有人报告，训练出一个打败它的模型。那个模型只有一个节点。

所以 Sourcegraph 的路线是：RAG 迭代快，不用收集数据集、不用烧算力、不用调损失函数，先把它用到极致。什么时候才微调？RAG 的各种路子都试过、还是到不了，需要模型层提升的时候。他们现在微调的目标很具体：特定编程语言的代码生成。模型在 Python、JavaScript 这种训练数据充足的语料上表现好，Rust、Ruby 就弱一些，MATLAB 这类长尾语言更差。先用 RAG，哪里不行补哪里。

顺带回答一个流行疑问：上下文窗口都百万 token 了，RAG 会不会死？Beyang 的答案是不会。现有长上下文基准大多是「回忆型」的，考模型能不能从窗口里指出某个东西存在。一旦要求同时关注多个东西、还要组合推理，性能掉得厉害。最好的架构永远是上下文窗口加定制化检索，两条腿走路。他们踩过的坑也在这里：把上下文塞给模型容易，让模型用对上下文难，既要有能力整合上下文的模型，又要把上下文摆成模型真正会用的格式。

评测的终极裁判是产品指标

Cody 有个设计原则：自由选择。聊天界面里可以直接切换 GPT-4、Claude 3、Mixtral。目前大多数人用默认的 Claude 3，GPT-4 有一批忠实粉丝，Mixtral 靠速度取胜。Beyang 前几天特意切回 GPT-3.5 做了个对照，它整合搜索结果和代码上下文的能力明显差一截。模型进步带来的变化很实际：他演示过一个股票追踪应用，指定 React 框架、Alpha Vantage API 拉行情、Recharts 画图，Claude 3 和 GPT-4 配上 Sourcegraph 的上下文能零样本生成整个应用，GPT-3.5 时代这做不到。

那 GPT-5 发布那天会怎样？他的回答是：希望当天就在 Cody 里上线，加几行模型配置的事。他们当然会跑自己的基准测试，但更看重产品数据和用户反馈。

更有意思的是他们对榜单的态度：评测能让你保持诚实，但别把它当终极标尺。他们过去选过榜单排名不靠前、日常用起来却更好的模型。基准里装不下的细节太多，全都影响最终体验。

最有权威性的指标是产品指标，尤其是接受率。补全是隐式触发的功能，用户没法决定什么时候要补全，所以看接受率和总量：总量代表价值大小，接受率代表到底是在帮忙还是在浪费人时间。一个模型就算 HumanEval 考第一，用户不按接受键，就是没价值。主持人 Jacob 感叹，很多公司宁可自己闷头做评测，都不肯把几个模型直接 A/B 测试给用户选，这让他意外。搭档 Pat 补了个类比：特斯拉把车开上真实道路收集数据，Waymo 在实验室里端到端打磨，两条路线的区别。

用户分层的数据也很有意思：代码补全更受初级工程师欢迎，对话功能的价值更多被资深工程师挖掘。初级开发者把它当教学工具，想要一个「大众做法」当起点；资深工程师的抱怨很一致，补全不够聪明，还打断心流，自己写更快。Beyang 有个精妙的类比：好学生从第一性原理理解知识、构建世界观，考完试知识还在脑子里；差学生考前一晚突击，把上下文塞满工作记忆，考场上拼凑着拿个及格分，表面看着对，细看全是逻辑漏洞。大模型就是那个突击型选手，问题是，开发者日常大量工作恰好适合这种模式，那就让机器干。

智能体的准备：先把验证器造好

外环自动化还没到，Sourcegraph 怎么准备？Beyang 说公司手里始终有一个实验组合，正在把现有的上下文能力和执行循环组合起来，投向一批适合全自动的问题。这里有个关键的子程序：验证器。智能体的游戏规则是生成一个足够正确的验证机制，再让 AI 想办法让它通过，通不过就把失败上下文喂回循环。测试生成对智能体是命门，对内环同样重要，人不测代码怎么知道代码能跑？

妙的是，做外环的功夫不会白费，那些子程序可以直接复用进内环工具。为自动化铺的路，今天就让人受益。

他们的长期定位也值得琢磨：新玩法不会都出自自己家，任何新的界面冒出来，高质量上下文能力都横切所有场景。所以除了少量自家应用，他们想把积木开放出去。用户一直在催 Cody 的 API，想接进自己的 CI/CD 流程。已有的自定义命令功能就是这个思路的雏形：你描述要拉什么上下文、给模型什么提示词、输出怎么渲染，就能造一个「生成提交信息」之类的命令。他们想让全世界的普通开发者都能在 AI 上构建，而不是养出一个专门的 AI 工具开发者阶层。

还有一个给工程管理者的隐藏彩蛋：Cody Ignore 功能本来是让客户屏蔽敏感文件，现在有用户要求扩展它，理由很直白，我代码库里的代码不都是好代码。Beyang 设想，以后工程负责人可以控制哪些代码进入 AI 的生成上下文，这可能是提升团队代码质量的新杠杆。毕竟没人因为代码写得漂亮拿工资，大家靠功能上线拿工资。

成本的态度也很松：推理开销涨得快，但模型成本长期一定会降，现在只做最低限度的控制，限流主要用来防滥用，省下的精力全部投到做价值上。

工程师会变多，活儿会变好

回到那个所有人都在问的问题：AI 会不会抢走程序员的饭碗？Beyang 的答案是，会，也不会。AI 会拿走你现在这份工作，但你会有一份新工作，而且大概率更好。他问过很多开发者时间都花在哪，真正写代码、发功能的时间很少，大头花在理解现有代码库、获取上下文、沟通协调上。

他创办 Sourcegraph 的初心就藏在这里：每个写过业余项目的人都体验过看着自己的作品活起来的火花，但职业开发者的日常，大部分时间被苦役占据。他想让 AI 把苦役拿走，把魔法时刻还回来。

总量上他判断工程师数量还会增长，先维持现有速度，中长期加速，只是「工程师」的定义会被重写。市场本身也在巨变：上一代技术的主题是软件吞噬世界，开发工具只是平台的附属品；现在，软件创造过程本身成了一个大市场，软件素养在扩散，AI 把创造软件的能力交到更多人手里。资本已经用脚投票，录制前后，Cognition 成立半年估值冲到 20 亿美元，Augment 拿了 2.5 亿美元，Llama 3 开源发布，70B 版本先行，405B 还在训练。

他担心的只有一件事：大玩家借这波洗牌搞垂直整合，把所有人锁进专有开发平台。他们这一代开发者赶上了 Web 和 Linux 主导的开放时代，是最大的幸运。所以他反复强调模型、代码托管、技术栈的自由选择权，同时和 OpenAI、Anthropic、Meta、Mistral 都密切合作。主持人问起供应商依赖的风险，他开了个玩笑：把宝押在单一供应商上很危险，万一哪天周五晚上，那家公司的董事会突然把 CEO 开了呢。全场心领神会，说的是 OpenAI 去年那出戏。

快问快答环节，他认为 AGI 的弥赛亚式叙事被严重高估，只靠堆 transformer 规模的论点「连错都算不上」。被低估的是形式化语言。自然语言不够精确，描述不了你要的东西，这就是数学存在的原因。当年牛顿和莱布尼茨通信只能用自然语言，后来他们发明了微积分的符号系统，因为英语又啰嗦又不精确。编程语言会一直存在，而且是 AI 越来越重要的互补品。

明天就能用上的几件事

这期播客信息量太大，挑几条明天就能动手的：

  • 做 RAG 先跑关键词搜索基线。别急着上 embedding 和向量数据库，先用 BM25 这类方案把基线立起来，能解释、能迭代。基线都打不过的复杂方案，不值得上。
  • 先做笨东西。新问题先上最简单的方案，快速迭代。RAG 路子全试过还不行，再考虑微调，而且瞄准具体短板，比如表现差的编程语言。
  • 让用户当裁判。模型评测跑一遍保持诚实就够了，把选择权交给用户，盯接受率和使用量这些产品指标，比内部评测集更接近真相。
  • 现在就写验证器。不管做不做智能体，测试生成和自动验证的子程序两头都用得上。为自动化做的每一步，今天就能改进人工流程。
  • 定价跟着价值走。Sourcegraph 用按月活跃用户计费取代传统席位制，用户当月登录并使用才计费。客户最烦为闲置席位买单，这个模式让付费和使用价值直接挂钩。

最后借用 Sam Altman 在 20VC 节目上给过的一个判断标准：判断一家 AI 应用公司好不好，就看模型突然变强十倍，它是高兴还是难受。Sourcegraph 显然是高兴的那种，模型越强，它攒了十一年的代码理解和检索能力就越值钱。
