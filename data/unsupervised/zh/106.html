《Jev 的创造者：2023 年的模型就够 AGI 了，为什么会计还没被自动化》

2023 年，GPQA 基准上的前沿模型已经超过 PhD 学生水平。同一年，OpenAI 内部流传一份文档，标题叫《我们本可以一年前就有 AGI》。写文档的人后来离职创业，做了个模型叫 Jev，名字取自杰文斯悖论。

这期 Unsupervised Learning，主持人 Jacob Effron 请到 TypeSafe 的 CEO、Jev 的创造者。发布一个月后复盘，聊的内容比模型本身有意思得多：为什么 labs 错过了机器原生的智能、benchmark 为什么已经失效、KV cache 怎么捆住 coding agent 的手脚，以及他为什么觉得 Anthropic 那一万多亿估值里有一部分建立在误解上。

一个解不开的矛盾

整场对话的起点是个老问题。AI 明明很聪明。GPT-3.5 时代的模型在很多任务上已经超过中等水平的人类，GPQA 这种连 Google 都搜不到答案的 PhD 级选择题，2023 年就被攻破。但翻宏观生产力数据，AI 的痕迹几乎看不见。

大部分人对这个矛盾只选一边站。信 AI 的人说革命马上来，看数据的人说这东西没用。很少有人给出像样的桥梁解释。他的解释是：智能被用错了地方。

他问过每一个早期员工、每一个投资人同一个问题。假设 LLM 是一个被软件调用的子模块，外面包一层 harness，可能就是个 while 循环。这些调用里，多大比例是为了人类消费，多大比例是为了机器消费？人类消费需要文风、韵律、可读性。机器消费要的是比特，字符串只在极端情况下才有用。

他说，哪怕是最“字符串脑”的人，给出的机器消费比例也是绝大多数。分歧只剩什么时候发生。既然答案是机器，为什么今天的模型全都在优化人类偏好？

他把这个叫“机器原生”的智能。Jev 的定位就是往那个方向走：一个给软件调用的认知核心，不需要讨人喜欢，需要可靠、可组合、行为可预测。名字里的杰文斯悖论也在这。效率提升会让总消耗增加，前提是这东西真的好用、真的便宜，让人到处撒。他的判断是现在还没到那个拐点，所以“回火”还没出现。

System One 模型，和一场斯德哥尔摩综合征

Jev 被命名为 System One 模型。内部有人反对，因为“系统一”在心理学里指直觉、快、会犯错的那部分，听起来像骂人。他的回应很直接：AI 被压缩成的形态就是系统一，诚实承认弱点本身有价值。

大多数人需要的就是系统一的东西。能快速判断、能处理模糊输入、能在有限上下文里做出够好的决定。问题在于，模型公司把这类能力包装成聊天机器人，让开发者以为自己在用一个无所不能的神谕。

他讲了个内部笑话：想让他回邮件，最好的办法是抱怨模型能力有缺陷。高管想约他，他推给 CTO 或销售负责人。有人骂模型不够聪明，他亲自下场 debug。他认为真正能推动路线图的是具体的 jaggedness，笼统的“再聪明一点”没有信息量。

他觉得整个行业陷入了斯德哥尔摩综合征。开发者习惯了模型公司按自己的单轨路线发东西，自己只能被动适配。他用《机器人总动员》里坐在椅子上被喂食的人打比方。人们规划未来时假设 AI 会变，却不觉得自己有 agency 去决定它往哪变。

人们应该多来向我们抱怨。这个领域还在一种斯德哥尔摩综合征里，觉得模型提供方走一条路，我们只是受害者。

他的判断是，这种被动状态既让人无力，也让整个领域错过了大量协作机会。开发者最清楚自己的下游应用需要多少可靠性、多少智能，他们比模型公司更懂。模型公司该做的是给对旋钮，把选择权交出去。Jev 发布时就带了一批“dreamer ready”的功能，明确说不推荐用在最稳定的生产场景，因为可靠性要求该由开发者自己定。

Benchmark 疲劳，以及别人替我们挖的护城河

Jev 发布后一个月，OpenAI、Cloudflare、微软都出了类似形态的模型。他的反应有点反直觉：别人在替我们挖护城河。那些模型更偏向 benchmark 优化，真实世界一用就露馅，会把开发者对整个品类的好感烧掉。

他说开发者已经对 benchmark 疲劳了。被“过度承诺、交付不足”骗了太多次，新模型发布时第一反应是等别人踩坑。这对 Jev 短期是好事，对领域是坏事。真有人做出好东西，也没有可信的渠道说出来。

发布时机也值得记一笔。当时正赶上“Pacing the Frontier”那场关于是否该放慢前沿能力的大讨论，所有人劝他别发。他的判断是那场讨论“从一开始就说不通，至少是不完整的”。

他把这套逻辑推到 AGI 定义上。OpenAI 的 AGI 定义是“完成世界上大多数有经济价值的工作”，他按工作量来理解。GPT-3.5 时代的模型就可能满足这个定义。那份《我们本可以一年前就有 AGI》的文档，说的就是这件事。

2023 年的模型已经能在很多维度上超过 PhD 学生，但会计、报销、对账这些“简单工作”还是没被自动化。他觉得这个反差本身就是线索：智能不是单一坐标轴，benchmark 测的那一维和真实工作需要的那些维，中间隔着巨大的工程鸿沟。

还有个他反复提的判断：模型公司都在一条轨道上优化人类偏好，没人做机器原生的智能。他用“labs 错过了它”来形容这件事。错过的不只是技术路线，还有一种产品哲学，把模型当软件组件而不是当聊天对象。

融资也是这个逻辑。他说服务本身能盈利，其实不需要那笔钱。融资是为了把最有用的人拉上船，因为团队完全不知道怎么做这门生意。比起估值，他更在意董事会里坐的是谁。

KV cache 的暴政

这是他讲得最兴奋的部分，语速明显变快。

几乎所有 coding agent 的 UX 设计都围绕 KV cache 做，因为缓存命中是最大的成本优化。代价是状态只能追加，像 iPython notebook，删不掉记忆。模型也被训练成习惯这种缓存，一旦你让它做花哨的有状态操作，它容易开始循环。

后果是一连串的。路由基本失效。如果每次调用都要带着缓存，你就没法先用便宜模型试、不行再升级。子 agent 很难做。给子 agent 传什么上下文、它返回后哪些该留，全靠猜。最安全的策略是全都追加，最后模型被越来越长的上下文拖笨。压缩必然丢信息。你不知道下一个任务会不会用到被压掉的那部分。

他想要的东西很具体：多个 agent 共享同一份上下文、按任务语义重新计算缓存、按预期价值决定保留什么。他管这个叫摆脱 KV cache 的暴政。

举了个例子。一个 agent 在改代码，另一个 agent 用便宜模型实时把改动可视化出来。今天的做法是等它“烹饪”完，再让它读 git commit 生成仪表盘。为什么不能共享状态，让可视化 agent 只读、实时渲染？

另一个例子是上下文压缩。今天的压缩是通用的，压完就丢了。如果压缩是按任务语义做的，检测到换了新任务就重算一份缓存，旧的那份还热着，切换成本会低很多。这些在他嘴里都是“完全可做的软件问题”，卡住的原因是整个技术栈都围着缓存命中率优化，没人愿意为了更大的架构自由度牺牲那点成本。

他还提了一个“语义依赖类型”的想法。今天的类型系统只能保证“返回一个 int”，如果类型可以写成自然语言属性，比如“返回一个大于零的 int”，下游就能拿到更强的保证，少写很多单元测试。这类东西他没说马上要做，但明显是他心里“软件加 AI 该有的样子”。

Anthropic、安全、多模态：几句不客气的话

聊到 Anthropic 的 IPO 和那吓人的估值，他没有直接看空，但拆得很细。coding agent 极有价值，可有多少使用真的产生净价值，是另一个问题。他猜很多定价里包含了对 AI 未来的误解，有人把“造神”当成了无限上行。

他给了整场最锋利的一句：如果说“让它们治愈癌症”是这一代版本的“让他们吃蛋糕”，那它会和玛丽·安托瓦内特那句一样，成为脱节的象征。

他还说，labs 最强的能力可能不是模型、产品或者分发，而是金融工程。那些算力交易的结构对主动承担风险的一方不一定友好，外面的人看不清这个老鼠窝有多深。市场不用因为技术不成立而崩，预期没兑现就够了。

AI 安全上，他把 ASI、生物风险、网络风险、trust & safety 拆成不同的事。关心 ASI 的人“与技术现实脱节”，得先真正构建过可靠系统，才有资格在房间里说某个东西会可靠地毁灭世界。他估计离真正的能动性还差几个“巨大突破”，一个都不一定够。把 Bostrom 的《超级智能》当现实读，让他担心。纸夹最大化器和“坏人用超级工具搞破坏”在他眼里也是两套完全不同的威胁模型。

还有个数字值得记：coding agent 对工程师的提效，他估在 20% 到 40%。取决于用例和用户水平。有些场景是无限倍，因为做的事以前根本做不了。有些场景和手写一样差。他觉得这和领域里看到的共识差不多。差距的来源是副作用：代码有 git、有人类在环、有办法回滚，其他知识工作没有这么齐的保险绳。所以他判断无人驾驶之外的很多自动化会慢得多。模型不够聪明不是主因，出错代价太高才是。

图像模型他更不客气。自家图像模型只有文本模型大约 10% 的成熟度，“说它 prod ready 我会不好意思”。多模态会降低智能可靠性，每个模态退化速率不同，这在 ML 圈是常识，只是聊天机器人把它糊成了模糊的人类偏好问题。他兴奋的方向是电子游戏、computer use、反 slop。computer use 尤其被低估：很多人不喜欢用电脑，却不得不用，AI 如果能可靠地替他们操作界面，价值比再写一个聊天框大得多。

明天就能用的几件事

这场对话里能直接拿走的东西不少。

  • 别把系统锁死在对某个模型的心智模型上。他说目标是像 SQL 一样 provider agnostic。今天用 Jev 处理这类任务、用别家处理那类任务，是务实的短期做法。把这种分工写死进架构，是长期负债。
  • 该用脏 hack 就用。原话是“如果你需要做最脏最烂的 hack 来给世界提供价值，我们不会拦你”。补一句，“如果你需要太多 hack，那还是我们的错”。
  • 停止追每一个新模型。生产软件里更新依赖是最烦的事，模型也一样。模型没好在能“扔后台跑一年不管”之前，追新就是给自己找活干。
  • 向模型公司抱怨具体的 jaggedness。抱怨“不够聪明”会被转给销售。说清楚“你在这个任务上会在第三步出错，导致我的下游不可靠”，才会被认真对待。
  • 评估模型别只看 benchmark。拿自己的真实任务跑一遍，哪怕样本很小。开发者被 benchmark 骗的次数已经够多了。

他最后说的一句话挺适合收尾：这个领域需要重新学会玩，而不是当模型公司路线图的受害者。软件加 AI 能打开的东西还很多，前提是有人真的去搭，而不是等着下一个 release 修好一切。
