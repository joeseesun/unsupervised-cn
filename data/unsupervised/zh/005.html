《拒了谷歌第400号工牌的哈佛教授：程序员是18世纪还没拖拉机的农民》

2002年，Matt Welsh 从伯克利拿到计算机科学博士，谷歌给他发了 offer。按他自己的说法，他大概会是谷歌的第400号员工。他拒了。

理由放到今天看有点荒诞：那个年代，顶尖博士的标准出路是当教授，去公司做研究属于退而求其次。于是他去了哈佛任教，带过的学生里有后来的 OpenAI 联合创始人 Greg Brockman，还有个选了他操作系统课的本科生，叫 Mark Zuckerberg。电影《社交网络》里那位上课的教授，演的就是他。

二十多年过去，他的履历变成了这样：哈佛教授；谷歌的首席工程师兼工程总监，带过 Chrome 旗下的几个团队；边缘 AI 公司 Xnor.ai 的平台负责人，公司被苹果收购后，他在苹果带过多个 AI 项目；OctoML 的工程 SVP，这家做模型部署优化的公司融资超过1.3亿美元。现在，他是 Fixie.ai 的 CEO 兼联合创始人，红点创投（Redpoint）最新一笔投资投的就是这家公司。

在 Unsupervised Learning 这期节目里，Welsh 讲了 Fixie 在做什么，也给出一个更大的判断：自然语言正在取代代码，成为人和计算机之间的主要接口。节目里还提到一个数据：开启了 GitHub Copilot 的代码仓库，新提交的代码有40%出自 AI。他把今天的程序员比作18世纪还没用上拖拉机的农民。下面把这一期的干货拆开讲。

先补一个时代背景。Welsh 读博那几年正值互联网泡沫的顶点，疯狂到什么程度？CEO 们会直接打电话到伯克利的办公室，向研究生毛遂自荐，就为了挖人。他给自己的定位一直很清楚：一个 builder，喜欢写代码，最开心的事是造别人用得上的东西。在哈佛待到学术休假，他去了谷歌，原计划一年后回学校教书，结果几个月后就发现回不去了。之前他写的软件，用户只有自己的研究生；到了谷歌，他第一次有机会造几十亿人会用的东西。后来从谷歌跳去创业公司，逻辑还是同一套：一款游戏打通关了，他更想换一款新的，同一款游戏里继续刷分这种事他没兴趣。至于为什么自己出来干，他的答案很诚实：在别人的公司里，个人能控制和影响的东西终究有限。回头看，创业比他当年以为的容易，只是那时候不知道该做哪些事，心里发怵。

Fixie 在做的事：让软件听懂人话

Fixie 的产品一句话能说清：帮企业把大语言模型接上自己的数据、系统和工具。但 Welsh 举的一个例子更值得展开。

假设你要写个程序，输入是一句英文：“帮我安排下周和 Erica、Jordan 开个会。”传统做法是什么？你得知道 Erica 和 Jordan 是谁，查到两人的邮箱，理解“下周”指哪几天，再读两个人的日历找空档。这是个相当复杂的软件，一个好程序员也得写上几周。

用大语言模型，做法变了：给模型看几个示例（few-shot），它就能学会调用 Google Calendar 的 API，把这件复杂事办成。用户和工具之间那层胶水代码，大部分不用写了。Welsh 管这叫“终极 no-code”。主持人接话说，no-code 这个词本身就怪，Welsh 补了个比方：这就像宣传自行车“不用汽油”，代码本来就不是目的，人要的从来都是结果。

Fixie 的核心抽象叫 agent。每个 agent 就是一个大模型加一小段代码，给某个现有软件包上一层语言接口：GitHub agent 负责把英文变成 GitHub API 调用，日历 agent 负责把英文变成日历操作。这样的 agent 堆多了，有意思的事情出现了：agent 之间用英文互相沟通，英语成了软件和软件之间的通用语。Welsh 的说法是，这像一个“用自然语言驱动、还加了类固醇的 Zapier”，任何东西都能连到任何东西。

他当天早上刚给人演示过一个自己都没料到的场景。他对 Fixie 说：画一张柱状图，显示某个 GitHub 仓库按提交数排名的主要贡献者。系统自己把任务拆了：先发现需要仓库贡献者数据，自己不会，就在系统里找能帮忙的 agent，找到 GitHub agent 拿回数据列表；接着又找来 Chart agent 把数据画成图。全程 Welsh 没指定任何步骤，只给了一句英文。过去要专门团队写几周的集成代码，现在变成写几个示例、包一层 agent。

主持人拿 ChatGPT 的插件系统来对比，Welsh 强调了两点差别：Fixie 不绑定任何模型供应商，每个 agent 可以各选各的模型；这套东西面向企业把模型接进自己的系统和工作流，ChatGPT 插件更像在聊天窗口里装几个小工具。

40%的代码由 AI 写下，从《Pong》到《荒野大镖客2》

聊到软件开发，Welsh 说自己现在离不开 Copilot，原话是“没它我活不了”。他讲了个很有画面感的细节：有天他调用一个不熟悉的库，按老习惯，得花五到十分钟翻文档或查 Stack Overflow，找出那八行代码怎么写。他懒得动，直接在代码里写了行注释“做下面这件事”，Copilot 把剩下的一口气补完了。

他的总结是：省下的远不止十分钟。真正的价值是人不用被打断。去查 Stack Overflow，半小时后你可能已经在刷 Reddit 了。

主持人补了一个数据：开启 Copilot 的仓库里，40% 的新提交代码来自 Copilot。另一位创始人的说法是，过去要几个月的活，现在团队几天干完。Welsh 找了个类比来说明这种速度有多反常：相当于计算机图形学在一个月内从《Pong》进化到《荒野大镖客：救赎2》。

“以前我的 IDE 里没有 AI，然后慢慢变好。实际情况是，之前完全没有 AI，然后突然就有了一个惊人的 AI。”

图形学的进化用了几十年，大家有时间适应。AI 给开发者的冲击没有缓冲期，所有人的心理预期都被打乱了。

600美元微调一个模型，寒武纪爆发要来了

节目里聊到开源社区的近况：Meta 的 Llama 流出后，斯坦福的 Alpaca、社区的 Vicuña 跟着出现，Databricks 放出了 Dolly，微调成本最低降到600美元。这几周的节奏比所有人预期的都快，Welsh 开玩笑说，南美的驼科动物名字快被用完了。

他的判断很明确：模型的寒武纪爆发不可避免，模型会彻底民主化、商品化。训练成本和时间还会继续往下走。往后看是两件事同时发生：通用基础模型大量涌现，在通用场景里互相竞争；更重要的，针对特定用途微调的模型会大规模爆炸。

Fixie 押的就是后者。它的每个 agent 可以用不同供应商的不同模型，还能为单个 agent 专门微调。逻辑很简单：GitHub agent 的模型不需要懂莎士比亚，也不需要懂文艺复兴艺术史，它只需要会说 GitHub API。拿一个更小更便宜的模型，微调到这个窄任务需要的质量，效果反而更好，推理成本低得多。

不做单一模型绑定，还有客户压力的成分。客户明确要求能换模型，原因排最前面的是隐私：敏感客户数据不能发给第三方，模型得能在企业自己的硬件上跑。Welsh 认为企业用自有数据微调出自己的模型，会和通用模型拉开差异，这里面藏着价值。

AGI、拖拉机，和一个六岁小孩

聊回他教授的老本行，主持人问他 AGI 什么时候到。他的回答分两层。第一层：我们不会有明确的时刻宣布 AGI 达成，没人能在某个周二早上宣布“AGI 解决了”。GPT-4 和 Bard 出来后，争论就已经开始，一个系统算不算有足够的智能，会长期吵下去。

第二层更值得记住：从早期的 Transformer 模型到 GPT-4，唯一的差别是更多的 GPU 和更多的数据，没有任何重量级的算法突破。如果这个外推继续成立，再多砸几亿美元硬件，能力就接着往上走。他的原话是，我们离机器智能追平人类“没有很远”，而且“这当然相当吓人”。他推荐了尼克·博斯特罗姆的《超级智能》。

社会怎么消化这件事？他用了工业革命的类比：农业经济转向工厂经济，机器接走了大量手工活，但没有造成大规模失业和饥荒，反而催生了以前不存在的行业，比如汽车制造。然后是那句流传最广的话：

“今天的程序员就像18世纪的农民，还在用手干活，其实他们早该有一台拖拉机了。”

主持人、前 GitHub COO Erica Brescia 把范围扩到程序员之外。她在 GitHub 管过支持团队，按她的观察，客服支持、HR 帮助台、要按席位买授权的 BI 工具，这些流程都会被重做。她提了个场景：直接用一句话，跨多个数据源问出一份报告，搁在以前得找人排期做。

节目末尾聊到孩子。主持人和 Welsh 的孩子年纪相仿，都在学写代码，一个学 JavaScript，一个学 Python。被问到怎么给孩子准备未来，Welsh 先承认推不动。他小时候想了解世界，得去图书馆，或者从书架上抽那本《芬克与瓦格纳百科全书》；现在的孩子随手就能查到任何东西。十年三十年后的世界长什么样，他说自己推不出来。

但有一件事他看得比较清楚：自然语言成为编程接口，意味着使用计算机不再需要专业技能，计算会向多几个数量级的人开放，不再存在一个替所有人写 App 的“祭司阶层”。一个还不会写字的六岁小孩，就能开口让家里的电脑替他自动化一件事，不用等哪家公司发布新 App。

主持人只能归结为一句“教孩子做个好人”。Welsh 接着讲了学术生涯教他的一课。1999年，他在伯克利的研究组，世界顶级的计算机科学项目之一，对未来的想象是：人们揣着 PDA，用红外点对点通信和街头信息亭交互。处在最前沿的人，也没能预见 iPhone 和 Wi-Fi。他的结论是，你对今天了解多少，和你能否想象未来，基本无关。

快问快答：什么被高估，什么被低估

节目结尾的老环节，Welsh 的回答都很干脆。

  • 被高估的：生成式 AI 整体。新用例每天都在冒出来，可多数东西停在演示层面。真正的难点是让 AI 深深嵌进产品的构建方式，别停在 demo。
  • 被低估的：AI 周围的工具和基础设施。现在建 AI 驱动的系统非常难，现成的机器很少。有人讥讽说这和三年前的东西没区别，他不同意：这是个新世界，问题不一样。
  • 政府该做什么：他希望政府先当 AI 的用户，别急着当监管者。AI 已经在不少政府职能里起关键作用，还能改进政府自身的运转。现在就重手监管不明智，没人真正知道未来长什么样，善意的监管很容易帮倒忙。美国目前的不干预态度，他希望延续。

明天就能用的三件事

这期节目信息量不小，挑三件明天就能上手的事。

第一，把 Copilot 这类工具的用法升级一下。别只让它补全代码，试试 Welsh 的招：写一行注释，把你要的东西用大白话描述清楚，让 AI 生成整段实现。核心收益是保住专注，别为八行代码跳去 Stack Overflow，半小时后发现自己刷着 Reddit。

第二，盘点你手头“胶水代码”性质的活。凡是把一句人话翻译成某个 API 调用的事情，查日历、拉数据、发通知、生成图表，都是 agent 模式的候选。挑一个最烦的，比如每周固定要做的“从后台导数据、贴进表格、发周报”，用几个示例喂给大模型试一次，成本可能比想象中低得多，微调一个专用小模型最低只要600美元这个量级。

第三，评估 AI 工具时加一条硬标准：能换模型吗？数据能不出内网吗？模型迭代这么快，绑死单一供应商的风险在放大，隐私合规更是迟早要过的关。Welsh 的客户已经在用脚投票，这份检查清单值得提前备好。想自己试试 Fixie，官网 fixie.ai 可以直接注册，他的 Twitter 是 @mdwelsh。
